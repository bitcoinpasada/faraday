# Themes on Material 3's colour system

**Kind:** Reference
**Status:** Built (owner, 2026-10-24; F113, `docs/decisions/F113.md`): the roles, the generator and the tables; every screen and component of Faraday and the Starter drawn on the roles by name; Settings › Appearance's Theme, Mode, Contrast and Reduce motion, the settings file's lines and the migration, the Starter's Appearance page; the theme tour. Not yet done: the website, the user guide's pictures and the README's screenshots redrawn in the new colours, and a custom seed colour picker (not scheduled).

Every theme is made again from the ground up on Material 3's colour
system, as if Faraday had used it from the start (owner, 2026-10-24). A
theme is one seed colour and one Material scheme style; Material's own
method (HCT, tonal palettes, roles taken from tones, contrast curves)
makes its colours, in Light and Dark, each at Standard, Medium and High
contrast. Screens and components take Material's colour roles by
Material's component specs. This replaces the colour parts of DESIGN §3,
F91 and F108; shape, type, spacing, motion and layout are unchanged.

What goes into the app follows `docs/STANDARDS.md` §0: a published
method (Material 3's colour system), followed in full and checked
against an implementation Faraday did not write (Google's
material-color-utilities, vendored and pinned, §10).

## 1. What changes

Today (DESIGN §3, `faraday/faraday-ui/src/pal/mod.rs`) the Dark theme's
39 colours are the keys, each other theme is a hand-written table of
what it draws each key as, and `Theme::color` finds a colour by its RGB
value. Fourteen themes: Dark, Light, Cobalt, five borrowed from other
projects, Bitcoin Orange and Bitcoin Orange Light, Lamplight, Mars and
two high contrast themes. Each table was tuned by hand to the contrast
tests in `faraday/faraday-ui/src/lib.rs`.

After this spec:

- Ten named themes, each a seed and a scheme style (§2).
- Mode (Light, Dark) and Contrast (Standard, Medium, High) are separate
  choices, so every theme has six schemes (§3). The two high contrast
  themes go; High contrast is a choice on any theme.
- The colours are Material's roles (§4), plus OK and Warning as
  Material custom colours (§5). Faraday's 39 names map onto them (§6).
- Each component takes the roles Material's component spec gives it
  (§7); state layers, disabled and elevation are Material's (§8).
- The tables are generated by material-color-utilities from the seeds
  and compiled in; Faraday ships the tables, not the HCT code (§10).
- The borrowed names are retired: Nord, Catppuccin, Gruvbox, Tokyo
  Night, Rosé Pine. A stored old theme maps to a new theme, mode and
  contrast, so no one's setting breaks (§13).

## 2. The themes

Each theme is a seed colour and a scheme style (material-color-utilities'
`Variant`). Tonal spot is the default style: Material's own default, a
calm primary at chroma 36 whatever the seed. Fidelity keeps the seed
itself as primary-container, for a theme whose colour must stay true.
Neutral keeps every palette near grey. Monochrome is Material's
greyscale scheme.

## 3. Mode and contrast

- **Mode**: Light or Dark, Material's `isDark`.
- **Contrast**: Standard, Medium or High, Material's contrast levels
  0, 0.5 and 1.0. Material's reduced contrast (below 0) is not offered.

A theme is the triple (theme, mode, contrast); `faraday_ui::Theme`
becomes that triple, each part its own type. Sixty schemes in all.

## 4. The roles

Faraday takes Material's role set from material-color-utilities'
`MaterialDynamicColors`, by the 2021 colour spec (`ColorSpec2021`, the
spec Material Web and the published Material 3 guidance use; §10.1 says
why not 2025 or 2026):

| Group | Roles |
|---|---|
| Primary | primary, on-primary, primary-container, on-primary-container, inverse-primary |
| Secondary | secondary, on-secondary, secondary-container, on-secondary-container |
| Tertiary | tertiary, on-tertiary, tertiary-container, on-tertiary-container |
| Error | error, on-error, error-container, on-error-container |
| Surface | surface, surface-dim, surface-bright, surface-container-lowest, surface-container-low, surface-container, surface-container-high, surface-container-highest |
| On surface | on-surface, on-surface-variant |
| Outline | outline, outline-variant |
| Inverse | inverse-surface, inverse-on-surface |
| Other | scrim, shadow |
| Custom (§5) | ok, on-ok, ok-container, on-ok-container; warning, on-warning, warning-container, on-warning-container; checksum, on-checksum, checksum-container, on-checksum-container |

Forty-five roles a scheme. Not taken, each for a reason:

- **The fixed roles** (primary-fixed, on-primary-fixed and the rest):
  colours that stay the same across modes; nothing in Faraday needs one.
- **background and on-background**: Material keeps them equal to
  surface and on-surface, for older code.
- **surface-variant**: replaced in Material by the surface-container
  roles.
- **surface-tint**: Faraday draws no tint overlay (§8).
- **The palette key colours**: inputs, not colours a component draws.

## 5. OK and Warning

OK (done, verified, can sign) and Warning (waiting, unsaved, needs
attention) are Material custom colours: a source colour harmonised with
the theme's seed by material-color-utilities' `Blend.harmonize` (the
hue turned towards the seed's by half the difference, at most 15°,
chroma and tone kept), made into a tonal palette.

- **Source colours**: OK #2E7D32 (Material's 2014 palette, Green 800);
  Warning #FFB300 (Amber 600).
- Monochrome takes the source colours as they are: its seed has no hue
  to turn towards.
- A status colour that would land near the theme's primary is not
  harmonised either (owner, 2026-10-24): Warning stays the source amber
  in Lamplight and Bitcoin Orange, and OK stays the source green in
  Forest. Every other theme harmonises both.
- **Roles**: each custom colour's four roles are built as Material's
  error roles are in `ColorSpec2021`, with the custom palette in place of
  the error palette: the same tones (40, 100, 90, 30 in Light; 80, 20,
  30, 90 in Dark), the same contrast curves against the same
  backgrounds, the same tone-delta pair between the colour and its
  container. So they follow Mode and Contrast as error does.
  material-color-utilities' own `customColor` (in its theme utilities)
  gives only Standard contrast; building the roles on its `DynamicColor`
  the way the error roles are built is how they get Medium and High.
- Error is Material's own error palette, as in every Material scheme;
  it is not harmonised.

Leaving them unharmonised keeps the source hue, but it does not move a
status colour away from a primary that already sits near it. The source
amber (HCT hue 79) is next to Lamplight's seed (82); the source green
(146) is next to Forest's (153). In Lamplight Light, warning is #7E5700
and primary #7A590C; in Forest Light, ok is #1B6D24 and primary #326941.
Bitcoin Orange's warning moves from #855400 to #7E5700, beside primary
#8C4F00. So in these themes, as with Mars's and Rose's primaries and
error, a status is told apart by its icon and words as well as its
colour. No state in Faraday is shown by colour alone.

**Checksum** is the codex32 booklet's pink (CODEX32 §7.5), a third
custom colour built as OK and Warning are, so the worksheets' checksum
squares are the booklet's pink in every theme: light on Light, a muted
rose on Dark.

- **Source colour**: #C57D81, the booklet's fill (`/pink`, RGB 1, 0.9,
  0.9, #FFE6E6: HCT hue 15, chroma 9, tone 93) at its own hue with chroma
  32 and tone 60, so its tonal palette carries the pink rather than a
  grey. Its container is #FFDADA in Light and #6F353A in Dark at
  Standard contrast, and its on-container #6F353A and #FFDADA.
- **Never harmonised**, in any theme: it names a colour printed on
  paper the person copies from, which no theme's seed changes. The
  rule above (a custom colour near the primary stays as it is) would
  keep it in Rose in any case.
- At Medium and High contrast its container darkens in Light and
  lightens in Dark, as error-container does, with its on-container
  turning to keep the contrast curve; the squares stay pink in hue.
- The worksheets use checksum-container for the fill and
  on-checksum-container for everything written on it (§6); checksum
  and on-checksum are generated with the rest of the custom roles and
  are not drawn yet.

## 8. States, disabled and elevation

- **State layers**: the content colour of a control laid over it at
  hover 0.08, focus 0.10, pressed 0.10, dragged 0.16 (Material 3's
  current states guidance; owner, 2026-10-24). Material Web's tokens
  (`v0_192`) still give 0.12 for focus and pressed; Faraday follows the
  guidance. These replace `STATE_FOCUS` 0.12 and `STATE_PRESS` 0.16 in
  `core/faraday-draw/src/tokens.rs`, and add `STATE_DRAG`.
- **Disabled**: content on-surface at 0.38; a container on-surface at
  0.12; an outlined control's edge on-surface at 0.12. A control not
  available now keeps its kind and shape (F108). These replace the solid
  `DIM` label, `STATE_OFF_FILL` and `STATE_OFF_FILL_HIGH_CONTRAST`; the
  opacities are named in `core/faraday-draw/src/tokens.rs`
  (`DISABLED_CONTENT`, `DISABLED_CONTAINER`).
- **Elevation** is shown by surface-container tones: a thing that
  stands higher takes a higher container. No tint overlay. Shadows are
  Material Web's two layers, key and ambient, in the shadow role, by
  level (`Canvas::elevation` already draws them).

## 9. High contrast

At High contrast the rules DESIGN §3 gives the high contrast themes
today carry over, as Faraday's own: no shadow, no fade at a scrolled
edge, the scrollbar at full strength, and a theme colour asked for
see-through drawn at full strength as an edge, a rule or a mark, and as
its edge alone where it would be a tint under text. State layers, the
scrim and disabled stay see-through as Material draws them; a disabled
control is not held to 7:1 (WCAG asks no contrast of it, and Material's
0.38 does not give it).

## 10. How the colours are made

### 10.1 The reference

Google's material-color-utilities, the TypeScript port, as published:
the npm package `@material/material-color-utilities` 0.4.0.

- **Source**: `https://registry.npmjs.org/@material/material-color-utilities/-/material-color-utilities-0.4.0.tgz`,
  SHA-256 `2f0b759749846357dd2d9ce0e1d5e8071e5b51bda24178b3d24ba75afa7f723d`;
  built from `https://github.com/material-foundation/material-color-utilities`,
  commit `eeaf82b8e11bf20f6d8da7c76336575b69e79e01` (2026-01-20, the
  package's recorded `gitHead`). Apache-2.0; its `LICENSE` is vendored
  beside it (SHA-256
  `8ded460ad5bd3ab9082eaa2f7502cc9bb621eaff87cecc55d823f21758707cea`).
- **Why this port**: it is the one Material Web and Material Theme
  Builder use, and its published form is plain JavaScript with no
  dependencies, so it runs offline under Node with nothing fetched. The
  Java original needs Android and Error Prone annotations; the C++ port
  needs Abseil; the Python packages are not Google's.
- **What is vendored**: the package's 45 `.js` files, its
  `package.json` and `LICENSE`, unchanged, under
  `tools/reference/material-color-utilities/…`, with a README giving the
  source, the commit, the tarball's digest and every file's SHA-256, as
  the cross-check's references do (`tools/reference/codex32/README.md`).
- **One shim, written here**: ten of the published files import a
  sibling without its `.js` extension (written for bundlers); Node's
  resolver refuses that. A resolve hook of a few lines, written here and
  named as Faraday's in the README, adds the extension to a relative
  import that lacks one. The vendored files stay byte for byte.
- **Spec version 2021**: every scheme is built with `specVersion`
  `'2021'` (the package's default). The 2025 and 2026 specs are Material
  3 Expressive's, tuned per platform (phone, watch); Material Web and the
  Material 3 guidance for these components use 2021, and fidelity and
  monochrome fall back to 2021 in any case.

### 10.2 The generator and the tables

- tools/themes/gen.mjs, Faraday's own: the ten themes (§2), the two
  custom colours with the themes that leave them unharmonised (§5), and
  the role list (§4). For each theme, mode and
  contrast it builds the scheme with the reference's scheme class
  (`SchemeTonalSpot`, `SchemeFidelity`, `SchemeNeutral`,
  `SchemeMonochrome`) and writes each role's colour.
- It writes one Rust file, `faraday/faraday-ui/src/pal/` gaining
  schemes.rs: one scheme a line, its 45 colours as hex words in role
  order, under a header naming the generator and the reference's commit.
  Sixty lines; the file is generated and not edited by hand.
- `just themes` runs it. It needs Node 22 or later and nothing else; no
  network.
- Faraday ships the tables, not the HCT code. A custom seed colour
  chosen at run time (not scheduled) would need HCT in Rust, checked
  against this same reference.

### 10.3 In Rust

- `pal::Role`: the 45 roles. `Theme` is (theme, mode, contrast), and
  `Theme::scheme` looks up its row of the table.
- A drawing call takes a paint: a role at an opacity, or a colour drawn
  as it is (a QR code, a camera's overlay, a stick's pill). `Ui` resolves
  a role through the current scheme. This replaces finding a colour by
  its RGB value (`Theme::color`, `Theme::has_role`), which needed every
  key colour distinct and breaks once two roles share a value (on-primary
  and surface-container-lowest are both white in many schemes).
- Every use is a role by name; the 39 old names are gone.
- Resolving a role is a lookup; drawing does no colour work. A change
  that touches every colour drawn is timed in a late-flow session before
  it is committed (`docs/SPEED.md` §7).

## 11. Tests

### 11.1 Material's contrast rule

For every theme, mode and contrast, the shipped colours meet Material's
contrast constraints as material-color-utilities' own test states them
(`dynamiccolor/dynamic_color_test.ts`, "constraint conformance test", at
the pinned commit), with the targets from `ColorSpec2021` at Standard,
Medium and High:

| Foreground | On | Standard | Medium | High |
|---|---|---|---|---|
| on-surface | surface-dim, surface-bright | 7 | 11 | 21 |
| on-surface-variant | surface-dim, surface-bright | 4.5 | 7 | 11 |
| primary, secondary, tertiary, error | surface-dim, surface-bright | 4.5 | 7 | 7 |
| outline | surface-dim, surface-bright | 3 | 4.5 | 7 |
| primary-, secondary-, tertiary-, error-container; outline-variant | surface-dim, surface-bright | none | 3 | 4.5 |
| inverse-on-surface | inverse-surface | 7 | 11 | 21 |
| inverse-primary | inverse-surface | 4.5 | 7 | 7 |
| on-primary, on-secondary, on-tertiary, on-error | primary, secondary, tertiary, error | 7 | 11 | 21 |
| on-primary-, on-secondary-, on-tertiary-, on-error-container | its container | 4.5 | 7 | 11 |
| ok, warning, checksum | surface-dim, surface-bright | 4.5 | 7 | 7 |
| on-ok, on-warning, on-checksum | ok, warning, checksum | 7 | 11 | 21 |
| ok-container, warning-container, checksum-container | surface-dim, surface-bright | none | 3 | 4.5 |
| on-ok-container, on-warning-container, on-checksum-container | its container | 4.5 | 7 | 11 |

The last four rows are Faraday's custom colours under the error rows'
targets. As Material's test does: the ratio is WCAG's, a target of 4.5
or less is a floor (met to within 0.05), and a target above 4.5 is met
or one of the two colours is already black or white, the furthest the
tone can go. surface-dim (Light) and surface-bright (Dark) are the
surfaces nearest the text, so a pair that holds on them holds on every
surface.

### 11.2 Faraday's floors

What screens rely on, tested on the shipped tables:

- On every surface role, at every contrast: on-surface, on-surface-variant,
  primary, error, ok and warning 4.5:1 or more; outline 3:1 or more.
- At High contrast, the same text roles 7:1 or more on every surface
  role, as the high contrast themes promise today.
- The board's and the worksheets' own pairs (§6), in the paints the
  screens draw them in: place text on its fill and band, stick text on
  its fill, paper and files text on their fills, vault text on its

### 11.3 The tables are the reference's

tools/lint-themes.sh, in `just lint`, runs the generator into a
temporary file and fails if it differs from the shipped table by one
byte, and checks the vendored files against their digests first. Offline,
under a second. A hand edit to the table, or a seed changed without
regenerating, fails `just lint`.

### 11.4 Behaviour

- A settings file with each old theme id (§13) opens in the theme, mode
  and contrast its row names; a file with `mode=` or `contrast=` keeps
  them; a written file read back gives the same choice.
- Settings: pressing a theme chip, a mode segment or a contrast segment
  changes what is drawn and what the settings file holds.

## 12. Settings

Settings › Appearance holds three rows, built from F108's components:

- **Theme**: ten chips, one per theme, each filled in that theme's
  primary-container in the mode and contrast on screen, with its name
  in that theme's on-primary-container (F120, owner 2026-10-25). The
  chosen one is ringed in that theme's primary and carries the tick.
  Cobalt carries the Default mark, as its tile does today. The chips
  wrap into as many rows as the width needs.
- **Mode**: a segmented button, Light · Dark.
- **Contrast**: a segmented button, Standard · Medium · High.

A change fades in over 350 ms, as a change of theme does today (MOTION
§3.5, F108). The Text size row (`docs/TEXT-SIZE.md`) sits under them
when it is built.

As built (C3, `faraday_ui::Ui::appearance`, `theme_chips`): on the wide
layout each row's label stands in a column `APPEARANCE_LABEL_W` wide
with its control beside it; on a small panel the label stands over its
control. A theme chip is drawn from that theme's own scheme in the
mode and contrast on screen (`Ui::theme_chip`): its fill
primary-container, its leading slot that theme's primary as a dot or,
on the chosen chip, the Done tick in on-primary-container, so the
choice does not rest on colour alone and every chip keeps one width
whichever is chosen. The chosen chip's ring is that theme's primary,
`THEME_CHIP_RING` (3 dp) thick and `THEME_CHIP_RING_GAP` (2 dp)
outside the fill, with the page showing between: primary stands 5.8:1
or more against the page in every scheme, while against its own
container it can fall to 1.4:1 (Cobalt Light, whose primary-container
is the seed's own dark blue), so a ring on the fill's edge would vanish
into it. In Dark primary is the lighter of the two; a ring darker than
the fill would vanish into the dark page (primary-container is as low
as 2.0:1 on it), so primary is the ring in both modes. The label on its
fill is Material's on-primary-container pair, 4.5:1 at Standard, 7:1 at
Medium, 11:1 at High (§11.1), and measured on the frame (§11.2). The
state layer is that theme's on-primary-container; while it shows
(hovered, focused, held) the label and tick go to white or black,
whichever on-primary-container leans to, since the pair has no room to
lose a tenth (Cobalt held fell to 3.89:1); held, every chip's label
reads 4:1 or more (6.5:1 at High). Mode
and Contrast are Material segmented buttons `SEGMENTED_H` tall, option
buttons where three segments do not fit the width (a small panel).
Under them, **Reduce motion**, a Material switch in a list row
(`Ui::switch_row`, MOTION §3.5), owner's addition of 2026-10-24.

Chosen rows elsewhere follow the same rule (owner, 2026-10-24): a chosen
card, option or row, a toggle that is on and the row of the place on
screen are Material's selected state, secondary-container with
everything on it in on-secondary-container (§7's segmented and filter
chip rows), not a tint of primary as C2 left them. At Medium and High
contrast secondary-container darkens in Light, so what sits on it moves
with it: a status word on a chosen row (a wallet's Can spend) is
on-secondary-container too.

## 13. Stored settings and migration

The settings file (`faraday/faraday-core/src/stick/settings.rs`) and the
kept set write three lines: `theme=<id>`, `mode=light` or `mode=dark`,
`contrast=standard`, `medium` or `high`. The header stays
`faraday-settings 1`: an older Faraday ignores the two new keys and a
theme id it does not know, and opens in its default.

A file without a `mode=` line was written before this change; its
`theme=` value maps as below. A file with `mode=` or `contrast=` takes
them as written, whatever its theme line says. The lines are read in
the order written and Faraday writes `theme=` first, so the theme line
sets the triple its row names and a `mode=` or `contrast=` line after
it sets that part (`Theme::from_stored`, `stick/settings.rs`). A theme
named since (`forest`, `frost`, `dusk`, `lavender`, `rose`,
`monochrome`) with no mode line opens in Light at Standard.

| Stored id | Theme | Mode | Contrast |
|---|---|---|---|
| `dark` | Cobalt | Dark | Standard |
| `light` | Cobalt | Light | Standard |
| `cobalt` | Cobalt | Light | Standard |
| `nord` | Frost | Dark | Standard |
| `catppuccin` | Lavender | Dark | Standard |
| `tokyo-night` | Dusk | Dark | Standard |
| `gruvbox` | Lamplight | Dark | Standard |
| `rose-pine` | Rose | Light | Standard |
| `bitcoin-orange` | Bitcoin Orange | Dark | Standard |
| `bitcoin-orange-light` | Bitcoin Orange | Light | Standard |
| `lamplight` | Lamplight | Light | Standard |
| `mars` | Mars | Dark | Standard |
| `high-contrast-dark` | Monochrome | Dark | High |
| `high-contrast-light` | Cobalt | Light | High |

Dark and Light were the plain modes; they become the default theme in
that mode. Each borrowed theme goes to the new theme nearest its accent
and page. The two high contrast themes go to High contrast: white on
black to Monochrome, black on white with a blue accent to Cobalt.

## 14. The Starter

The Starter draws from the same tables and roles
(`faraday/faraday-starter/src/draw.rs` uses `faraday_ui::pal` today) and
has the same three controls as Faraday, Theme, Mode and Contrast (owner,
2026-10-24). They are §12's rows, built from the same components, on an
Appearance page opened from the top app bar's ⋮ menu (`docs/STARTER.md`
§3.1d), a task page as About is, with the way back in the bar: as a
sheet, as first written, the ten chips and the two rows ran past the
foot of a compact window, and a Starter sheet does not scroll (C3). It
opens in Cobalt at Standard contrast, in Light or Dark as the operating
system's own setting asks apps (F126; Light when it says neither). The
Starter keeps no settings file (`docs/STARTER.md` §5.1), so a choice
lasts until it closes. The Faraday screens it holds draw in the same
scheme, and Faraday Demo inside it shares it: the Demo opens in the
Starter's theme, and a theme chosen in the Demo is the Starter's
(F126, `docs/STARTER.md` §5.3). The Text
size row (`docs/TEXT-SIZE.md`, the Starter's part) joins the same sheet
when it is built.

# F106 Faraday reads PSBTs, mnemonics and vaults as their standards say, and writes back what it read (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** formats

**Why.** The crypto cross-check (F79, `tools/crosscheck/README.md`)
listed where Faraday read more or less than a standard or its own
specification: a version 0 PSBT with version 2 fields, bytes after its
last map and a taproot signature whose sighash byte is 0 were read; a
version 2 PSBT's output without a script and BIP-370's invalid
required locktimes were read and used; `bitcoin` wrote some fields of a
read PSBT back otherwise than read (a taproot tree's leaf order, a
`PSBT_GLOBAL_VERSION` of 0 left out); a BIP-39 sentence typed composed
was refused; and `docs/VAULT.md` §7 and §8 said less than the vault
code checks, and more about a sheet's size than the reader held.

**Decision** (owner, 2026-10-23).

- PSBT: what BIP-370, BIP-371 and BIP-341 refuse is refused, by both
  the version 0 and the version 2 reader: BIP-370's twelve "PSBTv0 but
  with" vectors, bytes after the last map, a 65-byte taproot signature
  whose sighash byte is 0, a version 2 output without
  `PSBT_OUT_SCRIPT` (allowed only for a BIP-375 silent payment
  output), a required time locktime below 500 000 000, a required
  height locktime of 0 or from 500 000 000, and wrongly sized fallback
  locktime, modifiable flags and required locktimes, checked on reading.
- PSBT (Q1): for fields Faraday does not change, a PSBT is written
  back exactly as it was read; the original bytes of untouched fields
  are kept (a `PSBT_OUT_TAP_TREE`'s leaf order among them) rather than
  rust-bitcoin's writer patched.
- PSBT (Q2): a `PSBT_GLOBAL_VERSION` of 0 is kept as read.
- BIP-39: `Mnemonic::parse` reads the sentence in NFKD, as BIP-39
  requires, so composed input (French and Spanish accents, Japanese
  kana, Korean syllables) is accepted. `unicode-normalization`, already
  a test dependency, becomes a dependency of `faraday-bip`; its
  `tinyvec` exemption is raised to safe-to-deploy (not reviewed,
  `docs/deps/unicode-normalization.md`).
- Vault (Q3): a GPG key record's (type 7) field 2 and a signing-round
  record's (type 9) fields 2 to 4 are required, as the code has them;
  VAULT §7 says so.
- Vault (Q4): a recovery-sheet payload over 16 KiB is refused on
  reading, as the writer refuses one and §7 caps it.
- Vault (Q5): an empty passphrase is refused at create; VAULT §8 says
  so.
- Vault (Q6): a vault with two type 14 records for one key, or two
  type 10 records for one transaction, is refused on reading (and not
  written), the refusal naming the key or the transaction.
- The cross-check's known differences for all of these become
  agreements, checked on every run.
- The owner approved shipping `tinyvec` as "not reviewed" in the app
  (2026-10-23).

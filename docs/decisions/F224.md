# A kernel patch of Faraday's own on the Pi: the bootloader's seed is not credited unless the command line says to (2026-11-08)

**Kind:** Record
**Status:** Active
**Area:** security
**Held by:** repo.kernel-patches

*Makes one more exception to F153's "No kernel patch of Faraday's own", as F205 and F221 did: the rest of that rule stands.*

**Why.** F102 says the Pi's pool is ready on the kernel's jitter alone, with every
other source mixed in and none counted. The Pi's firmware always writes
`/chosen/rng-seed`, and on 32-bit ARM the kernel reads and credits it before it
parses the command line, so `random.trust_bootloader=off` comes too late and
the pool counted as ready at the first line of the log. The firmware has no
setting that leaves the seed out.

**Decision** (owner, 2026-11-08). The Pi's kernel carries one line more:
`trust_bootloader` starts false in `drivers/char/random.c`. The seed is still
mixed into the pool; only `random.trust_bootloader=on` credits it. It credits
less and never more: no new reach, no new code, no kept copy of anything.
Tested on a Pi 3B+ before it was approved for main: `random: crng init done`
moved from 0.000000 s, right after the machine model, to 0.17 s, right after
bcm2835-rng registered. That generator was credited until F102's part for it was
built; it is mixed and not credited now. The patch is carried through every kernel update and goes when the
kernel reads the command line before the device tree's seed, or the firmware
can leave the seed out. `docs/KERNEL-PATCHES.md` entry 0004 says the rest.

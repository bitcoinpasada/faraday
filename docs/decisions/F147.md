# F147 One Pi image per screen for every Pi, the Pi 4 among them, one build per visit to the download page, and images published for testers (2026-10-28)

**Kind:** Record
**Status:** Amended by F150
**Area:** release

*Amended by F150 (2026-10-28): the Pi 4 is approved on the terms its reach asks.*

**Why.** A person choosing a download knows which screen they have
before they know which Pi model they have, and a download page that asks
several questions, or lets several builds be ticked, loses people before
they download. The Pi 3B, 3B+ and Zero 2 W share one chip, one kernel and
one firmware; only their device trees differ, and the Pi's firmware loads
the device tree of the board it starts on. It picks the kernel file by
board the same way, so the Pi 4's 32-bit kernel and firmware can sit on
the same card, under the same system. A panel can only be tried
on hardware someone has, so waiting for every panel to be tried before
its image is published keeps the images that most need testers from
them.

**Decision** (owner, 2026-10-28; `docs/IMAGES.md` §3, §4, §7).

- **One Pi image per screen and build, for every Pi Faraday supports.**
  Each Pi image carries the device trees of the 3B, 3B+ and Zero 2 W, and
  the firmware loads the one for the board it starts on. There is no
  separate Zero 2 W image. A DSI screen does not fit a Zero 2 W, which
  has no DSI connector, and its download says the Pi 3 and Pi 4.
- **The Pi 4 is planned, on the same images.** Each Pi image gains the
  Pi 4's kernel, firmware and device tree; the system on the card is the
  same 32-bit one. What the Pi 4 adds to the kernel's reach (USB behind
  PCIe, a boot loader in the board's EEPROM) is written out for the
  owner before it is built, and whether the 2.8-inch runs on the Pi 4's
  firmware display path without DRM, which Strict needs, is tried on
  the board. The Pi 5 comes after the Pi 4.
- **One build per visit to the download page.** The page opens on a
  tile for each piece of hardware; one tile leads to one build's page,
  which offers the Starter for the visitor's system and that build's
  image. Strict or Open is not asked first: each tile takes Strict where
  the hardware has it, and its page offers the other build.
- **An image is published before it has been tried on its hardware**,
  marked on the download page as looking for testers, and marked tested
  once it has been tried there.
- **Hardware planned but not yet built** has a tile marked coming soon,
  which leads to no download.

**Amends** F145: its website that lets a person tick one image or
several, and `docs/IMAGES.md` §3's rule that an image is tried on its
panel before it is published.

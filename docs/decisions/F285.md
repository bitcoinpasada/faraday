# F285 Make new parts replaces a key's Seed XOR set, and an old part still kept stays on the plan (2026-11-17)

**Kind:** Record
**Status:** Active
**Area:** backup
**Held by:** review

*Amended by F293 (2026-11-19): a plan's SLIP-39 set that is not its key's gives way to the key's, its placed shares kept on the plan as old shares until destroyed, and Convert's Rotate the set records the new set on the key whose set it rotates; the rest holds.*

*Amends F276 (2026-11-16): a key that has a Seed XOR set may have it replaced by Make new parts on Back up; "one set of a kind per key" still holds for the set in use, and the rest of F276 holds.*

**Why.** A second split of a key that has a Seed XOR set was refused, so a
person who lost a part, or wanted a different number of parts, had no way
on: Convert has no set actions for Seed XOR. Every old part is needed to
rebuild the key, so one old part destroyed makes the rest worthless; but
a person may keep some, or all, and the plan has to say where they are
and what they still rebuild.

**Decision** (owner, 2026-11-17).

1. **Make new parts.** On Back up's Seed XOR section, a key that has a
   set offers **Make new parts** in place of the split buttons. It splits
   the key again (2 or 3 parts, as the first split), and the new set
   replaces the old one at once: the key's facts become the new set's,
   and the plan's current set with them. The new parts are placed one to
   a place, as a first split's are.
2. **The old parts.** Each old part the plan placed stays at its place as
   a kept old part, counted, until the person says otherwise. The section
   then lists each old part by its number and place with **I destroyed
   it** (it leaves the plan) and **Still kept** (it stays, marked). A kept
   part's chart sheet offers **I destroyed it** later. An old part the
   plan never placed is not on the map and is not asked about.
3. **What identifies a kept part.** Its seed and its own master
   fingerprint (public, already kept as the old set's fact), never its
   number in a set: `What::XorKept(seed, fingerprint)`, written on a spot
   line as `xork{seed}.{8 hex digits}`. The old set is kept whole on the
   plan as one line, `xorold {seed} {fingerprints}`, as a codex32 set
   rotated away is (`rotated`). A plan holds at most four old sets of a
   seed, and a fingerprint is in at most one of them; Make new parts that
   would break either is refused until older kept parts are destroyed. An
   old set's line is dropped once none of its parts is on the map.
4. **What a kept part counts for.** An old set rebuilds the key only
   while every one of its parts is still on the plan, wherever they are:
   then "any one place lost" and what a place's finder holds count it as
   the set it is. One part destroyed and the old set rebuilds nothing.
   Old and new parts never combine. A kept part has no checklist item and
   no Check my copy; the parts item counts the new set only. Where every
   old part is still kept, the section says so: "Every old part is still
   kept: together they rebuild this key."
5. **Where it is stored.** The kept parts are the plan's only (the plan
   record, `docs/VAULT.md` §7 `faraday.plan.{n}`). The key's
   `faraday.xor` (binary field 7) keeps one set, now the new one; its
   layout does not change. A plan with no kept part writes no `xorold`
   line and no `xork` token, so it is the same bytes as before. An older
   Faraday reads a plan with either as a plan it cannot read (an unknown
   line or spot token is refused), and keeps it as read, named, unused.
6. **A plan whose set is not its key's.** A plan made by another wallet
   using the same key, or read beside a key whose facts changed, holds a
   set that differs from the key's. Opened, its placed parts become kept
   old parts and the key's set becomes its current one, not placed yet:
   the safe reading, since the person has not said they are destroyed.
7. **Only Back up replaces.** Convert a seed still records a set only on
   a key that has none; a second split there is not recorded.
8. **Not a security trade-off.** A kept part records its seed, its
   fingerprint and its place, never a word; no new copy of secret data,
   no new `unsafe`. A whole old set still kept is counted as the exposure
   it is.
9. The spec is `docs/BACKUP-FLOW.md` §17.26.

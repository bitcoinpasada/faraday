# F336 The leak tests look at live memory, the secret types' own wipe and the screen, never at freed memory in general: the freed scan and its named entries go (2026-11-27)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** tests (app), tests (domain), tests (root)

*Amends F250 (2026-11-27): point 1's freed-block failure ("every freed copy counts") and point 4's
named entries in `tools/leak-entries.toml` go; its other points hold. Amends F281 (2026-11-27):
point 3's "the leak tests of F250" now means the live, wipe and screens tests of this record; the
rest of F281 holds.*

**Why.** `main`'s leak tests failed on a test secret in any freed block, with a known freed copy
let through only by a named entry. F281 had already put a copy left in freed memory outside the
security model, and on the device every lock restarts the app and the kernel zeroes freed pages,
so a freed copy does not outlive the lock. The scan kept looking for what the security scope
leaves out, and failed on every new freed copy, often inside a library, until an entry was
written. The owner was asked on the specification's review and answered in chat on 2026-11-27:
"drop the freed scan".

**Decision** (owner, 2026-11-27; `docs/spec/07-tests.md` §6 holds the detail).

1. **No freed scan.** No leak test scans freed blocks in general, and no freed copy is listed:
   `tools/leak-entries.toml` is not carried, and no leak test has an entry or another way through.
2. **Live memory.** After a screen that held a typed, scanned or shown secret is left, and after a
   lock, no live block of the process holds a form of the planted secret (F281 point 2).
3. **The types' own wipe.** Each of Faraday's own secret types is tested to wipe what it holds:
   a test drops one value and finds no form in the blocks that one drop freed
   (`Leak::drop_checked`). That reads freed memory, but only the type's own blocks.
4. **The screens.** A planted secret drawn, or a kept image of one left, at the frame after a
   lock, a hide or a page left fails (F250 point 2, as 04 V19 and F337 now bound the kept images).
5. **The allocator stays, smaller.** `faraday-leak-scan` lists live blocks and reads freed ones
   only inside `drop_checked`; it is a test-only allocator and nothing of it ships.

# F233 Compare two PSBTs lists their differences without judging them; a fee bump is said only on Faraday's own rule, failing closed (2026-11-10)

**Kind:** Record
**Status:** Active, nothing built
**Area:** signing
**Held by:** keys.fee-bump-rules

**Why.** A wallet on the online side builds a replacement for a stuck
transaction and sends it to the device as a new PSBT. A wallet that is
wrong or hostile can change a payment in it, and the review of one PSBT
cannot tell that from what the person meant. Only a comparison with the
person's own copy of the original can. BIP-125 says what a node relays
as a replacement, not what a replacement pays, so whether it "only
raises the fee" is a rule no standard defines.

**Decision** (owner, 2026-11-10; `docs/COMPARE.md`).

1. **Compare two PSBTs**, a tile in Tools' Transactions group after
   Check a signer, lists how two PSBTs or finished transactions differ:
   inputs matched by outpoint, outputs by script (equal amounts paired
   first, then in index order), position never a difference. It judges
   nothing: its lines carry no tone.
2. **The fee bump result** is shown between an original and a
   replacement (different unsigned transactions spending an outpoint in
   common), in Compare (First as the original) and on Sign a
   transaction's review, there only when Files holds another
   transaction spending the same inputs. "Only the fee is raised" needs
   every rule of COMPARE §3.2: every original input spent; an added
   input the person's own; sequences kept or neither a relative lock;
   shared amounts the same; no outpoint spent twice; the same version,
   and the same locktime unless both are none or a block height; the same payments, by script and amount, an amount
   higher counting as changed; both fees known, the fee and the fee
   rate both higher. An output is the person's own only where the
   inspection verifies it against a loaded key or a registered wallet,
   or its script is verified so on the other side.
3. **Fails closed.** A rule that fails on what the files state is "More
   than the fee changed"; one that cannot be worked out (an amount not
   stated, a key origin of a key not loaded, an original that states no
   key origins and loses an output) is "Cannot tell", never the first
   result.
4. **A statement, never a gate.** The result does not stop signing; the
   review's own checks stand as they are. It names the file it compared
   against, since Faraday cannot tell whose copy a file is.
5. **Not cryptography of Faraday's own.** It reads amounts and scripts:
   F177's label does not apply. It is a review rule with a STANDARDS
   row, checked against what Bitcoin Core's `psbtbumpfee` makes.

A change to any of these rules is a new decision.

**Where:** `docs/COMPARE.md`; `docs/SIGNER-CHECK.md`; `docs/STANDARDS.md` §0.

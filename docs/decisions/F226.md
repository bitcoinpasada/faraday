# F226 A QR vault is made and opened in a tool in Tools, never kept open, and a file vault's item can be saved as one (2026-11-08)

**Kind:** Record
**Status:** Active
**Area:** security
**Held by:** review

*Amends F189 point 6 (2026-11-08): a QR vault is no longer made empty by Create a vault, listed on Vaults while open, or changed and saved again on a page of its own; what it holds, its one length and its contents' TOML are kept.*

**Why.** The owner keeps the QR vault in the app but out of the backup
flow (F217, withdrawn), and asked for it in two places: a tool in Tools
to make and open one, and on a file vault's item, a way to save that item
as one (owner, 2026-11-05). A QR vault holds one item and is made whole
each time, so keeping one open beside the file vaults, with a page, a
seal at Save and a state across the lock, would add a second kind of open
vault for what a tool does in three cards. The Krux code tool (F219) is
that shape already: it makes a code and keeps nothing when left.

**Decision** (owner, 2026-11-05 and 2026-11-08).

1. **A tool in Tools.** The tile **QR vault**, in the Vaults group, opens
   a tool with **Make** and **Open**. It keeps nothing when left, at the
   idle warning or at a lock (owner, 2026-11-08). A QR vault is never
   listed on Vaults and never sealed at a lock; to change what a code
   holds, a new one is made. Create a vault makes file vaults only.
2. **Make** takes a typed note or a loaded key of 12 or 24 English
   words, a passphrase typed twice with a warning line and no minimum
   beyond not being empty, a memory step and a name, and gives the code,
   its labelled PNG and its `.pgp` file. A key's words are sealed inside
   `faraday-keys` and never lent to the tool.
3. **Save as a QR vault** is on a file vault's seed, codex32 share, BIP-39
   passphrase and note, and on nothing else: a person's password entry
   gets none (owner, 2026-11-08), nor does any item a QR vault's
   contents have no place for. The item stays in the file vault.
4. **An item too long still shows the button** (owner, 2026-11-05); its
   press opens a dialog saying so. For a note the dialog says how many
   characters to take off its end to make it fit, a character being what
   Backspace takes, so the count is right for accented letters and emoji;
   a passphrase or a key gets no count, since a shorter one is another
   secret. The text is plain statement of fact, in `faraday-strings`.
5. **Open** takes a code from any scanner that takes a SeedQR, or a
   `.pgp` file in Files, asks its passphrase, and hands what it holds
   where that item goes: words to the seed sheet, a share to Add a key's
   codex32 form, a passphrase to its loaded key, a note to **Save as a
   note** in an open file vault. What it opened to is held in
   `faraday-keys` and leaves only through those, under a named reveal of
   its own.
6. **No scan back.** Neither Make nor Save as a QR vault offers to scan
   the printed code back: an item saved from a file vault stays there,
   and a typed note was typed from somewhere. Open is the check.

**What it is not.** A QR vault stays not a secret under `docs/QR.md`
§7.1 (F189, F190): this changes where it is made, not what it is.
`faraday-pgp`'s message and `faraday-vault`'s `qr` do not change.

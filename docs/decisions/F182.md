# F182 A stick Windows leaves whole: the image's first usable sector and boot FAT, a stick the Starter makes for its size, the boot partition kept as released (2026-10-31)

**Kind:** Record
**Status:** Active
**Area:** stick
**Held by:** review

**Why.** Every stick written from the image is bigger than the image,
so its backup GPT is not at the disk's last sector. Windows 11, within
a plain plug-in, rewrites the primary header for the disk's size and
moves the entries' place to the first usable sector less 32: sector
2016 on the image, which holds zeros. The primary then fails its CRC,
and Linux, macOS and the Starter's keep data see no Faraday stick until
a PC's firmware repairs it. Shut down with a stick in, Windows also
writes three values in the boot partition's FAT32, so its SHA-256 is no
longer the release's. Both were found and tried in a Windows 11 virtual
machine (`docs/STICK-IDENTITY.md` §2).

**Decision** (owner, 2026-10-30 and 2026-10-31). It amends F174, whose
own serial for each FAT volume becomes the data partition's alone, and
whose check after writing becomes, on a stick, the boot partition's;
and F80, whose 128 MiB data partition becomes the least a stick has.

1. **The image** (STICK-IDENTITY §4.1). Both GPT headers give sector 34
   as the first usable sector, the partitions unmoved, so a table
   Windows rewrites stays whole. The boot FAT32 is built as Windows
   leaves it: FAT[1] `0xFFFFFFFF` in both FATs, FSInfo's next-free hint
   the first free cluster, worked out from the volume and never fixed.
   The build checks both with `sgdisk -v`, `sfdisk --verify` and
   `fsck.fat -n`. The GPT read-only attribute is not used.
2. **The Starter makes a stick for its size** (§4.2): a table for the
   whole disk (the backup at its end, first usable sector 34, the
   stick's own GUIDs), the release's boot partition, and a data
   partition from sector 133120 to the last usable sector, formatted
   FAT32 at that size by Faraday's own formatter (F180), with its own
   serial and the person's name. The Pi card keeps the image's sizes:
   its MBR has no backup for Windows to move.
3. **The boot partition is the release's byte for byte**, its FAT
   serial included, on the stick, the Pi card and in keep data. The
   disk and partition GUIDs, the Pi card's disk signature and the data
   partition's serial stay each stick's own.
4. **The check after writing a stick** (§4.3): the boot partition read
   back byte for byte and, without a signed boot file, against the
   published `-boot.vfat` SHA-256, which the payload's manifest carries;
   the table and the data partition against what the Starter made. The
   screen says "The boot partition matches the release". The Pi card's
   check stays the whole image's.
5. **The layout** (§5.1): the data partition at sector 133120 of at
   least 128 MiB, ending at or before the disk's last usable sector;
   everything else exact, and every reader fails closed on any other.
6. **A reused stick's free space** is left as it is; Clear the whole
   stick first is an option, which shows its estimated time before it
   starts.
7. Sticks made before get no line in the release notes.

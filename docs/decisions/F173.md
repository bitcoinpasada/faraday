# F173 A TOTP setup code read with no vault open shows the read card (2026-10-29)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** keys.home-scan-takes-all

**Why.** F167 had a scanner for anything that reads a TOTP setup code
with no vault open say so in one line, "That is a TOTP setup code.
Unlock a vault to add it", and stay open: the person had to leave the
scanner, find the vault, unlock it and scan the code again, and with no
vault at all the line named one that did not exist.
`docs/SCANNING.md` §4.5 and §5 give every scanner a read card with the
way over to the flow that takes what was read.

**Decision** (owner, 2026-10-29; `docs/SCANNING.md` §10 item 1). This
amends F167's second item for a TOTP setup code and vault entries;
the rest of F167 stands.

- A TOTP setup code or vault entries read on a scanner with no vault
  open show the read card, never Files, in place of F167's one line.
- With a vault in Files but none open, its way over is **Unlock
  {vault}**: the code is carried through the unlock, and the new
  entry's form opens filled once the vault is open. It is wiped once
  Unlock is left, by a lock, Back or Cancel there.
- With no vault at all, its way over is **Make a vault**, and the code
  is not carried: the card says "Not kept · scan it again once the
  vault is open", the code is wiped at the press, and Create a vault
  opens empty of it.
- With a vault open, a scanner for anything still opens the new entry's
  form filled, with no card (F167).

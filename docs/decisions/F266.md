# F266 The Linux Starter always draws its own close button (2026-11-14)

**Kind:** Record
**Status:** Active
**Area:** starter
**Held by:** review

**Why.** A tiling desktop on Linux (Hyprland, Sway, i3) draws no title
bar, so the Starter's window there has no close button, and only the
compositor's key closes it. Whether a desktop draws one cannot be found
out: winit reports what the window asked for, not what is drawn, and
neither xdg-decoration, xdg-shell's capabilities nor X11's frame extents
say whether a close button is on screen (`docs/STARTER.md` §3.1d). Material
3 has no close button in a top app bar for a desktop window; a window's
close is the system's.

**Decision** (owner, 2026-11-14).

1. On Linux the Starter draws its own close button, always, as the last
   item of the top app bar, on Wayland and X11 alike; never on Windows.
2. On a desktop that draws a frame (GNOME, KDE, Xfce) the window has two
   close buttons, the frame's and the Starter's. The frame stays, since
   turning it off would take minimise, maximise and the resize edges with
   it.
3. The button does exactly what the window's own close does: the Starter
   closes, Faraday Demo returns to Home (F126), and during a write it
   holds until the write ends.

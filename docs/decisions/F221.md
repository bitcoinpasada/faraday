# F221 Two more kernel patches of Faraday's own on the Pi: a 32-bit framebuffer with red first, and vc4's output polling stopped on unbind (2026-11-06)

**Kind:** Record
**Status:** Active
**Area:** security
**Held by:** repo.kernel-patches

*Makes two more exceptions to F153's "No kernel patch of Faraday's own", as F205 made one: the rest of that rule stands.*

**Why.** Two things on the Pi could not be had without changing the kernel.

- The app's frame is red first, and vc4's framebuffer was 16 bits, so the
  shell converted every changed pixel on the CPU before each write, and the
  screen showed 5 or 6 bits a colour. A 32-bit framebuffer with red first is
  written as it is. Measured on a Pi 3B+, conversion and write together, in
  separate runs: about 3.1 ms to 2.3 ms a write on the 2.8-inch panel and about
  21.9 ms to 18.7 ms at 1080p, and 8 bits a colour.
- vc4 starts the output poll's delayed work and never stops it. The Pi's boot
  unbinds and binds vc4 again to bring up the DPI panel, which frees the device
  while the timer is pending, so a Pi with the 2.8-inch panel panicked about
  13 s after power-on.

**Decision** (owner, 2026-11-06; `docs/KERNEL-PATCHES.md`, `docs/IMAGES.md`
§3.2).

1. **The Pi carries these two patches of Faraday's own**
   (`faraday/image/boards/pi3/linux-patches/0003-…` and `0004-…`).
   0003 makes vc4's framebuffer emulation 32 bits and red first, and the
   changes it needs in the generic framebuffer emulation (on 6.1 also in the
   DRM client, which 6.18 has upstream). 0004 stopped vc4's output polling
   when the driver unbound. Neither adds a
   device node, command, permission or interface: the app writes `/dev/fb0` as
   before.
2. **No network code** goes into the kernel for either.
3. **Each goes when it is no longer needed:** 0003 when a kernel the Pi moves
   to lets vc4 ask for this format itself, or if the shell goes back to
   converting each frame; 0004 when a kernel the Pi moves to stops the poll
   itself, or the boot no longer unbinds vc4. Any kernel update has to carry
   them or show they are not needed. 0004 went with the move to Raspberry
   Pi's 6.18: vc4 there sets up polling with `drmm_kms_helper_poll_init`,
   which stops it when the device is released.
4. **Any other kernel patch of Faraday's own needs its own decision** (F153).

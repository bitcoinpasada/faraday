# F300 Faraday reads back an extended private key and a master seed in hex (2026-11-20)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** tests

*Amends `docs/SEED-CONVERSION.md` §1 item 6: a key loaded from an xprv
holds only its master key, and Convert offers it its xprv alone.*

**Why.** The owner (2026-11-20): Convert a seed already writes a key's
master seed in hex and its xprv (F88), but nothing reads either back, so a
person who kept one cannot load it. The owner decides to accept more than
before: both are read back wherever a key is taken. Both are BIP-32's own
forms: the seed a master key is made from, and the extended private key
it serialises to. Faraday already decodes an extended key by its own
strict reader, because `bitcoin` accepts seven of the sixteen keys
BIP-32's vector 5 rejects (`docs/STANDARDS.md` §0 and its list of rules
not in a decision).

**Decision** (owner, 2026-11-20, with its details chosen in the
question box the same day; `docs/KEY-FORMS.md` §6).

1. **Taken where a key is taken.** Add a key, Convert's From and every
   screen that takes every form read both, as forms of the registry
   (F299), under **Other forms**. The Inbox finds a file holding one, as
   it finds words, SLIP-39 and codex32 files, and loads it only when the
   person opens it.
2. **An xprv: a master key only.** It is decoded by the strict reader
   inside `faraday-keys`. Its depth, parent fingerprint and child number
   are shown. At depth 0 it loads as a key that holds a master key and no
   words or seed. Any other depth is refused with the line that it is not
   a master key: no origin is guessed. An origin written before it is
   taken only where it names the key's own fingerprint and no path.
3. **Its version names its network.** `xprv` on Bitcoin and `tprv` on a
   test network; the other is refused by name, and so are SLIP-132's
   private spellings.
4. **A hex seed: BIP-32's seed.** 16 to 64 bytes, an even count of hex
   digits; any other length is refused. It has no scan kind, since 64 hex
   digits are also a transaction id or a hash and 16 or 32 bytes may be
   BIP-39 entropy: it is read only where the person chose the hex seed
   form. It loads as a seed key does.
5. **No passphrase** for either, and **no copies**: the backup plan
   shows a key loaded from an xprv as kept outside the plan and makes no
   paper or file copy of it.
6. **What stays refused stays refused.** A non-master xprv, an xprv of
   another network, an extended key any rule of vector 5 rejects, a bare
   xpub without its origin, and a seed of no BIP-32 length.
7. **Checked.** BIP-32's test vectors 1 to 3 load and give their published
   fingerprints and master keys, every key of vector 5 is refused, and the
   keys they make are checked against an implementation Faraday did not
   write. The reading is an action of the cryptographic manifest (F148).

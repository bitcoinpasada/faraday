# F155 The other refusals of input a standard allows: keys, wallet files, PSBTs, transfers, shares, the vault and the paperkey (2026-10-28)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** standards.refusals-stay

*Amends F90 (2026-10-23): F90's list of refusals of input a standard allows gains the refusals below, which STANDARDS §6 listed without a decision.*

**Why.** F90 records where Faraday refuses input its standard permits,
and each refusal there is the owner's decision. The manifest
(`docs/crypto/actions.toml`) named more refusals of that kind that no
decision recorded. Each one fails closed: a refusal costs a person a
file or a key that another wallet would take, and accepting it would
cost a check Faraday could no longer make.

**Decision** (owner, 2026-10-28). F90's list gains these refusals:

- A BIP 39 passphrase outside printable ASCII or over 256 bytes is
  refused. BIP 39 allows any NFKD text. A wallet made elsewhere with
  such a passphrase cannot be restored here; in exchange, the same
  typed letters always give the same seed, on any keyboard and any
  normalisation.
- Restore takes a seed for a wallet's key slot only when the seed's
  whole extended public key at the slot's path matches the wallet's
  key. BIP 32 and BIP 174 identify a key by a four-byte fingerprint.
  Four bytes can collide, and a wrong seed taken for a slot would sign
  for a wallet it does not hold.
- A multisig key with no origin is refused where a wallet policy reads
  it. BIP 380 allows a bare extended key. Without an origin, the device
  cannot find which of its keys signs or prove that change is the
  wallet's own, and a guessed path is not taken.
- A SLIP-132 version (`ypub`, `zpub`, `Ypub`, `Zpub` and the rest)
  that disagrees with the script or the path around the key is refused.
  SLIP-132 names a version for each script but does not ask a reader
  to check it. A key labelled for one script and used under another
  shows addresses that the wallet which wrote it does not watch.
- A Caravan file whose `startingAddressIndex` is not 0 is refused, and
  so is an Electrum multisig keystore with no master fingerprint. Both
  formats allow them. The device derives addresses from index 0 and
  needs every key's origin to sign, so it would show other addresses
  than the file's wallet, or be unable to sign.
- A `musig()` wallet with a script tree is refused, and only its key
  path is built. BIP 390 allows `musig()` in a taproot tree. A
  script-path spend of an aggregate key is not built or checked here.
- A key origin of more than 16 steps anywhere in a PSBT is refused when
  it is read. BIP 32 allows a depth of 255 and BIP 174 sets no limit.
  Signing derives a key along each path, so a long path costs work the
  file asks for, and no wallet's path is that long.
- A SegWit v0 input that has only a witness UTXO, in a transaction of
  several inputs, is refused. BIP 174 allows it. Its amount is the
  coordinator's word alone, and two rounds of that lie pay the
  difference to the miner.
- The signed-amount memory refuses a transaction stated again with
  other input amounts. BIP 174 lets a signer sign a PSBT each time it
  is asked. A coordinator that states one amount to get a signature
  and another for the same transaction is running the two-round fee
  attack.
- A key signs only where the PSBT's origin names it under the master
  key's fingerprint, the key derived there is the one named, and the
  input's script holds it. An origin under an account's fingerprint
  matches no key. BIP 174 lets a signer find its keys however it likes.
  A key found any other way could sign an input the person was not
  shown as theirs.
- BBQr frames over 4,096 characters, and transfers over 360 KiB put
  together or decompressed, are refused, as are Specter transfers of
  more than 1,000 parts. Neither format sets these limits. Without them,
  a picture or a QR stream could ask for memory and work with no bound.
- A codex32 string with a character outside the bech32 alphabet (other
  than `?`) is refused rather than read as unreadable, and more than 8
  unreadable boxes that are not one run are refused. BIP 93 makes the
  first optional and allows any pattern the code corrects, and
  python-codex32 accepts both. A guessed erasure, or a correction past
  where it is unique, could propose another secret.
- A SLIP-39 secret above 256 bits is refused. SLIP-39 allows any even
  length of 128 bits or more. The secret is the BIP 32 seed of a key
  Faraday holds, and its buffers are sized to 256 bits; a longer secret
  is refused rather than cut.
- A vault header with Argon2id lanes other than 1, more than 10 passes,
  or memory outside 8 MiB to 4 GiB is refused before any derivation.
  RFC 9106 allows wider parameters. A file could otherwise make the
  device spend hours or allocate memory it does not have before it
  says whether the passphrase is right.
- A paperkey restore that cannot make every signature of the
  certificate again, equal, is refused. The `paperkey` tool joins the
  secret to the public key without that check. A restore taken on the
  public key alone could carry a secret that does not make the key's
  own signatures.

All are kept: they fail closed. Each is revisited if a real file, share
or set is refused.

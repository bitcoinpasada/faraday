# F240 Make a new wallet asks who signs, then a single key's backup (2026-11-10)

**Kind:** Record
**Status:** Active
**Area:** wallets
**Held by:** review

*Supersedes F107 (Single key, backup in shares). Amends F112 (its tooltip
moves from the Kind card to the Backup card) and F115 (no backup in
shares kind has its Keys card passed over).*

**Why.** Under F107 a single key's backup was chosen twice, back to back:
on Kind (Single key, or Single key, backup in shares) and again on New
key's Start (BIP-39 words, or Codex32). The two routes gave different
results (only one named the set on Check), the Kind card mixed who signs
with how the seed is backed up, codex32 shares were offered for native
SegWit alone, and Change on Start reopened forms that the end of the
flow then refused.

**Decision** (owner, 2026-11-10; `docs/FLOWS.md`, Make a new wallet and
New key; `docs/CODEX32.md` §6.9).

- **Kind** asks only who signs: Single key or Multisig, with the address
  types and MuSig2 behind **More kinds**. "Single key, backup in shares"
  is no longer a kind.
- A single key, of every address type, has a **Backup** card right after
  Kind: **Words (BIP-39)** or **Shares (codex32)**, nothing ticked at
  first, a row pressed moving on (F103). Where Make codex32 shares is not
  offered the card has one form and is not shown. A wallet made from
  another takes its keys and has no Backup card.
- The codex32 scheme is asked where the shares are made: Make codex32
  shares' own Scheme card (2 of 3, 3 of 5, Other), which for a wallet's
  key does not offer "None, the secret alone".
- **New key** opened for a single key's slot offers one way to make a
  key, the Backup card's form, beside every way to add a key you have
  (words, a SeedQR, codex32 strings, SLIP-39 shares, Seed XOR parts);
  Make SLIP-39 shares stays under Other forms there. No key put in the
  slot is refused: a codex32 set you hold fills a codex32 backup's slot,
  and any key you have fills either.
- A multisig cosigner's slot makes BIP-39 words only: neither codex32 nor
  SLIP-39 shares are made there, so no share threshold stacks on the
  quorum. A key of any form already held fills any slot, as before.
- **Check** names the set ("Backup · codex32 w0za · 2 of 3") for a single
  key made here as codex32 shares, whatever its address type; Back up
  opens on codex32's standard way for it (`docs/CODEX32.md` §9.5).
- F112's tooltip on "codex32" stays, the one explanation on a working
  screen: it is on the Backup card's **Shares (codex32)** row, where the
  person chooses a backup they may not have heard of.
- A backup flow kept across a lock under the old kind (kind code 10) is
  read as Single key, native SegWit, its Backup card answered Shares
  (codex32).
- **Touch targets.** The Backup card's closed row is a step row like the
  others of Make a new wallet, and on the stick's 1024 × 600 panel those
  rows are under the touch floor (`docs/M3-CHECKS.md` §3, the small
  panel's step rows, a defect): the count of Create's step rows there
  rises from 3 to 4 (owner, 2026-11-10). The cure is the step rows'
  height on that panel, for every flow at once, not this card's.

**What it does not change.** On chain a single key is what it was: one
descriptor, one xpub. Restore never offered the old kind and is
unchanged. New key on its own (Tools, Add a key) offers every form.

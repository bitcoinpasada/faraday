# F121 No codex32 strings for a key of words (2026-10-26)

**Kind:** Record
**Status:** Active
**Area:** backup

**Why.** For a key of BIP-39 words, codex32 strings encode the 64-byte
BIP-32 seed the words and passphrase make, as 127 characters. They give
back the same wallet but never the words or the passphrase: a one-way
conversion with the passphrase in it. The owner did not ask for it and
does not want it.

**Decision** (owner, 2026-10-26; `docs/CODEX32.md` §9,
`docs/BACKUP-FLOW.md` §17.23). Codex32 strings are a backup only of a
key whose secret is a codex32 set already (made by Make codex32 shares,
or loaded from strings). A key of words is offered none: not in
Customize backup or the plan, not in the copies by hand. A key with a
set keeps its form, Check my copy, Add a share, Replace a share and
Rotate the set. A plan saved earlier with a set the plan was to make
loads with that form dropped and the rest read as written.

This amends F93: the backup's copies by hand and the backup plan no
longer make a codex32 set, and the 127-character length is no longer
offered.

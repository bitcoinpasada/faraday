# F272 An area's glue lives in that area's folder; lib.rs holds none (2026-11-15)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** structure.impl-faraday

*Amends F253's list of files with an inherent `impl Faraday` (its "only shrinks" wording); the rest of F253 holds.*

**Why.** `faraday-core`'s `lib.rs` held two `impl Faraday` blocks of about
a hundred functions between them: the frame, the pointer, presses, the
lock, the stick's storage, the toast, the self-test and more. A reader
looking for what a press does or how the lock ends had to search a file
that also holds the struct, the types of the screens and the code map,
and the file kept growing with each area's glue. `docs/STRUCTURE-PASS.md`
§7.1 already says an area's code is in its folder.

**Decision** (owner, 2026-11-15; `docs/STRUCTURE-PASS.md` §7.2, §7.3).

1. **The glue of an area is an `impl Faraday` in that area's folder.**
   `lib.rs` holds the struct, its `Default`, the code map, the module
   declarations and the `App` implementation (a trait implementation is
   one for the whole type), and no inherent `impl Faraday`.
2. **The list is one file per area.** `tools/lint-layout.counts` names
   the files allowed an `impl Faraday`; a file is added there when an
   area gets its glue, and `lib.rs` is never on it. The list no longer
   only shrinks; the top-level field count of `Faraday` still does.
3. **The move changed no behaviour:** each function kept its text, and
   a function called from another module became `pub(crate)`.

# F164 The manifest's screens_not count is 24 (2026-10-29)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** crypto.action-covered

**Why.** `tools/lint-crypto.counts` holds how many `[[action.screens_not]]`
entries `docs/crypto/actions.toml` has: a screen whose code calls an
action's root and does not offer the action (`docs/CRYPTO-LEARN.md` §9.2).
The count only falls, and raising it is the owner's decision (F74). It
read 23 when the vault's seal count came in, whose unlock added two
entries (CreateVault and Vaults read a copy's seal count through
vault-unlock's roots and open no slot); the check was not yet part of
`just lint`, so nothing failed. words-identity's Silent entry, which the
tree no longer needs, has gone since. Each of the 24 left is needed: with
it removed, `docs/crypto/gen_how.py`'s screens check fails.

**Decision** (owner, 2026-10-29). The count is 24. The entries are the
vault module's screens that serve every vault screen without doing the
action (descriptor, seedqr-make, vault-reveal and kdbx on CreateVault,
Unlock and Vaults; vault-create on Unlock, VaultContents and Vaults;
vault-unlock on CreateVault and Vaults; vault-load on CreateVault and
Vaults; gpg-create on CreateVault, Unlock and Vaults), and gpg-create's
BackupFlow and Family, which read a GPG key's fingerprint and make no key.

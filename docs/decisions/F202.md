# F202 A USB pointer approves itself by pressing targets in a row while nothing trusted can point, and tries at a target are counted for the session (2026-11-04)

**Kind:** Record
**Status:** Active
**Area:** security
**Held by:** tests

*Amends F153 (2026-11-04): a held device gets no sheet until it is used, tries at a target are counted for the session, on a touchscreen as on a pointer, and a touchscreen presses as many targets in a row as a pointer.*

**Why.** A receiver with only a mouse paired shows as a keyboard node and a
mouse node, each held apart. The sheet shows the first, the keyboard, which
asks for a typed code and offers only Ignore. A held pointer's motion and
press stop in `held_wake` (`faraday/shells/stick/src/main.rs`), so a machine
with nothing trusted that can point has nothing that can press anything, and
it stays so until it is powered off. A trusted keyboard does not change that:
it cannot aim, and a mouse with no arrow looks dead on a machine with only a
keyboard (owner, 2026-11-04). A pointer can show a person is at the screen as a
touchscreen does (F153, item 2): a device that cannot see the screen cannot
aim.

Reading the code also found that F153's count does not bind. `missed` is per
device and `kept_out` rises only on a third miss, so a device that presses
twice and then re-enumerates (`gone`) or presses Ignore (`ignore`) leaves no
count and gets a fresh target. Every node held when the limit is reached
also keeps its tries, since `admit` looks at the limit only on arrival.
Tries at a target are therefore unbounded today, and a pointer given the same
rule would inherit that.

**Decision.**

1. **Which input.** A pointer node with no letter keys may approve itself
   only while nothing trusted can point: no device on the machine's own bus,
   and none believed, that is a mouse, a touchpad or a touchscreen is still
   being read (`alone`). A trusted or believed keyboard does not count. With a
   trusted pointer a person can already press **Use this pointer**, which keeps
   working; a held pointer stays as it is today and gets no arrow, because it
   would be moving a person's own arrow and it needs nothing. This is the
   narrowest rule that frees a machine with only a USB mouse, with or without
   a keyboard. While a pointer's targets show and a trusted or believed
   keyboard exists, Enter on it lets that pointer in, as **Use this pointer**
   does, once the sheet has been drawn and that keyboard quiet for a second
   (`ENTER_QUIET_MS`): an earlier Enter does nothing, so a mouse that moves as
   a person ends a passphrase with Enter gains nothing by it. The sheet has no such button, since a press there from the
   held mouse would count as a wrong try, and it carries one line saying so,
   shown only with such a keyboard. A held keyboard's keys never reach this:
   they stay in `held_wake`. Nothing is trusted by name. A machine that
   reports a built-in keyboard it does not have stays stuck as it is today.
2. **The targets.** Once it is used (item 8) the pointer gets the sheet F153 gives a touchscreen: a
   target at a place drawn from the session's seed, Ignore at the foot, the
   whole screen, no press beside it as a way out. The arrow shows from the
   sheet's first frame, whenever the sheet comes up, and then follows that
   pointer. There are several in a row,
   each place drawn separately, and a touchscreen takes the same rule, since
   it shares the sheet and the odds. How many comes from the room the sheet
   leaves and `TOUCH`, not from a table of screens: the fewest that make a
   session's chance (item 7) no worse than a keyboard's. If no count Faraday
   draws would do that, as in a room too small to hide a target, the sheet
   shows no target and the device stays out. A person sees which target of how
   many. Before the seed, no target, and a press on anything but Ignore counts
   for nothing.
3. **What moves while it is held.** Only the device whose sheet is showing, and
   only while the sheet is `NewInput`, moves the shell's cursor and arrow. The
   core is told only that a device was used, and a press: no hover, drag, wheel,
   Back or Forward. A press is the button going down (or a pad's tap) at the
   cursor, which reaches the core as the `InputTapped` a touchscreen sends; the
   cursor keeps no press afterwards, so a release has nothing to send and the
   press that lets a device in presses nothing else. Motion from any other held
   device moves nothing, and under another sheet or screen no held motion moves
   anything.
4. **What the device learns.** Nothing. The shell opens the node read-only and
   writes nothing to it; the arrow is painted on the panel. Its position is
   not secret either: the cursor starts mid-screen and stops at the edges, so a
   blind device can place it as a touchscreen places a tap, given the screen's
   size. That is why the chance below is the same as a touchscreen's.
5. **Presses.** A press on the target showing brings the next; a press on the
   last lets the device in. A press beside it is a wrong try and restarts from
   the first, at the same place as before. The third wrong try keeps that
   device out until it is unplugged and adds to `kept_out`, as for a
   touchscreen. A press on Ignore keeps it out and counts nothing: a blind press
   there only removes the device, and a person who does it by chance plugs it
   in again. A press counts against the target it was aimed at: one that lands
   on a target already pressed, before the next is drawn, is no hit on the next
   and no wrong try, so pressing one place quickly gains nothing. A press with
   input already believed lets the device in at once, as F153 has it: it comes
   from a person, and the targets are there for what has no other proof.
6. **The count for the session.** Every wrong try at any target, pointer or
   touchscreen, adds to a count that unplugging and Ignore do not clear. At nine
   (`KEPT_OUT_LIMIT` times `TAP_TRIES`, what F153 meant) or at `KEPT_OUT_LIMIT`
   devices kept out, every held device waiting on a target is kept out at once,
   and new keyboards and touchscreens are ignored, and new pointers too
   while `alone`, until Faraday starts again. The toast names what is ignored.
   With a trusted pointer a new pointer is still asked about. A keyboard's letters
   keep their own rule: they leave by the same two doors, but at about
   13 windows in 17^6 they are not worth a count.
7. **The chance, and what it is not.** A target's box is `TOUCH` square and its
   place uniform in the room left for it, so a blind press lands with chance
   `TOUCH`² over that room. A session has at most nine wrong tries, so at most
   nine runs at the targets, and a run needs every press to land: with `n`
   targets a session's chance is at most nine times that chance to the `n`. A
   keyboard's is 39 windows in 17^6 (13 in each of three keyboards' 18 letters),
   about 1 in 620,000, and `n` is the fewest that stay under it. Worked from
   tokens and line heights at Display scale 100%, not measured:

   | Screen, in layout units | One press | Targets | A session, about |
   |---|---|---|---|
   | A USB touchscreen beside the 2.8-inch panel, 268 × 358 (the panel's own touch is trusted and has no test) | 10.8% | 7 | 1 in 650,000 |
   | 7-inch, 964 × 565 | 0.82% | 4 | 1 in 25 million |
   | 1280 × 720 | 0.41% | 3 | 1 in 1.6 million |
   | 1920 × 1080, or 3840 × 2160 at its doubled density | 0.15% | 3 | 1 in 33 million |
   | 2560 × 1440 | 0.08% | 3 | 1 in 220 million |

   A pointer believed this way can press anything a person's can, blind; it
   cannot let in a keyboard, which needs the code read from the screen, and it
   cannot press Enter on a trusted keyboard. A person watching sees the arrow
   move by itself. A device left plugged in gets a
   session's tries at each start.
8. **A held device asks when it is used** (owner, 2026-11-04). This is one rule
   for every held device, whether or not other input is trusted. At plug-in a
   small notice names the device and nothing blocks. A held pointer's first
   motion or press brings up its targets, or its dialog when a trusted pointer exists; a held touchscreen's first touch brings up its targets; neither
   counts as a try, since nothing was drawn to aim at. A held keyboard's first
   key brings up its code, and a letter counts as it does now. A device that
   never acts never asks, stays held and is never believed, so a receiver's six
   nodes ask only for the one a person uses, and a mouse let in leaves its
   receiver's keyboard node quiet. One sheet shows at a time: a device that acts
   while another's sheet is up waits its turn, in the order they acted, and its
   proof and counts are unchanged. Using a device gives it no extra try, since
   item 6 counts them all. A rogue device can bring up its sheet by acting, as it
   could by being plugged in before; one that stays silent asks nothing.
9. **No lock-out from this.** A node that stays silent counts nothing and costs
   nothing, and neither does Ignore. Only wrong tries and wrong letters count. A
   person who reaches the limit, or whose device is burned through it by another,
   starts Faraday again.
10. **A keyboard with a pointer.** Neither is believed because of the other.
    Across nodes there is no link: each proves itself. On one node, the code
    lets in both kinds, as it does today (`inputs.rs`). Such a node gets no
    target, since a press would give its keys a keyboard's power at a pointer's
    proof; with no keyboard actually paired it stays stuck as it is today, and
    splitting one node's input by kind is not done here.
11. **Saying a device is in.** The toast exists, but `notices` draws it with the
    page, before the sheet, so when another node waits the next sheet covers it.
    That is how a keyboard can be approved with nothing seen. The toast is drawn
    over the new-input sheet too, and says the kind: "Keyboard in use: {}",
    "Pointer in use: {}", "Keyboard and pointer in use: {}",
    "Touchscreen in use: {}". The name alone does not say it, as a receiver's
    nodes share one.

**Not changed.** A USB touchscreen still approves itself whether or not other
input is trusted (F153). Touch on a bus that is part of the machine, as the
2.8-inch panel's is, stays trusted input with no test.

# F222 On a Pi's HDMI screen, fades start off (2026-11-07)

**Kind:** Record
**Status:** Active
**Area:** design
**Held by:** tests

*Sets the first-start default of Reduce motion (`docs/MOTION.md` §3) for one screen; nothing else about motion changes.*

**Why.** At the full HDMI mode (1080p) frames are slow on a Pi 3, below 30 a
second on heavy screens, and a fade drawn in steps then shows as stuttering.
The owner tried the dev image on an HDMI monitor and accepted this (owner,
2026-11-07).

**Decision.**

1. **The stick shell tells the app when the connected screen is an HDMI
   monitor** rather than the device's own panel: `Event::ExternalScreen`,
   sent when the DRM HDMI connector is connected and gives an EDID.
2. **Reduce motion is on until the person chooses.** Only a choice is kept in
   the settings file; a choice kept or made wins, so fades can be turned on in
   Settings. A choice made on HDMI stays when the same card later runs on the
   2.8-inch panel.
3. **The 2.8-inch panel keeps its fades**, and a shell that never sends the
   event keeps the default of motion on.

**Against Material.** Material's motion guidance has transitions on by default
and leaves a reduced-motion setting to the platform. This is a difference: on
one screen the default is the reduced form, because the screen cannot draw the
transitions smoothly. The person can turn the transitions on, so nothing
Material requires is withheld.

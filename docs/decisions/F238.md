# F238 Named costly operations are held by an instruction count in the check (2026-11-10)

**Kind:** Record
**Status:** Active
**Area:** speed
**Held by:** speed.op-count, speed.op-count-raised, speed.cost-stated

*Sits beside F69 (costly work takes the compute token), which says who
does costly work; this holds how much it costs.*

**Why.** A cost was stated in a document and never measured, and looking a
word up became slow without any check noticing. The budget tests count
drawing only: whether a frame does costly work, not how much a costly
operation costs. Wall-clock time depends on the machine and on what else
it is running; the number of instructions a run executes under valgrind
does not, in practice.

**Decision.**

- Named costly operations are held by an instruction count in the check.
  `tools/op-cost` runs each once on a fixed public test vector;
  `tools/op-cost.py` (`just lint-op-cost`) counts the instructions under
  valgrind's callgrind and compares them with `tools/op-cost.counts`. An
  operation more than 25% over its count fails, and so does an operation
  with no count and a count with no operation. A fall does not fail; the
  run says to lower the count (`--write`).
- A count is raised only in a commit that says why (review rule
  `speed.op-count-raised`). A new costly operation that a person waits for
  is added to `tools/op-cost` with its count.
- A cost stated in `docs/SPEED.md` or `docs/COMPUTE.md` says how it was
  measured, or says it was not measured (review rule `speed.cost-stated`).

The check needs valgrind (`docs/DEVELOPING.md` §1); GitHub Actions
installs it for the part that runs this lint only.

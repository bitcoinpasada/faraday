# F335 A silent payments wallet's record is kept in the vault file's `silent` field (2026-11-25)

**Kind:** Record
**Status:** Active
**Area:** vault
**Held by:** tests

**Why.** Save wallet wrote a silent payments wallet's record text into the `descriptor` field of its entry, and the reader takes a `policy` that parses or a `descriptor` that reads as one, so the entry came back damaged.

**Decision** (owner, 2026-11-25; `docs/VAULT.md` §7, the item table).

1. A `wallet` entry has exactly one of `policy`, `descriptor` and `silent`; two or none is a damaged entry.
2. `silent` holds the record text of `SilentWallet::to_text`. It is written only for text that `SilentWallet::parse` takes and whose `to_text` gives the same bytes; it is read only by `SilentWallet::parse`, and a text whose `to_text` differs (CRLF, a trailing newline, extra spaces) is a damaged entry with a bad value, never read as a descriptor. It is not protected, as `policy` and `descriptor`.
3. A silent record in `policy` or `descriptor` stays damaged: there is no fallback for entries saved before the field.
4. A Faraday without the field reads the entry as damaged (it finds neither `policy` nor `descriptor`: a field missing), lists it as Unreadable and writes it back as it was.

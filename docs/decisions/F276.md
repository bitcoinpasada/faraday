# F276 A Seed XOR set and a SLIP-39 set made on the device are counted on a wallet's backup plan (2026-11-16)

**Kind:** Record
**Status:** Active
**Area:** backup
**Held by:** review

*Amends F204 (2026-11-04): its "nothing is remembered; no vault, plan or backup changes" no longer holds for a set Convert a seed makes of Seed XOR or SLIP-39, which can be counted on a wallet's plan; the rest of F204 holds.*

**Why.** A backup made in Tools was invisible to the wallet's plan and to
Backups: a Seed XOR part or a SLIP-39 share on paper was not on the plan,
so no check counted it and no place's loss was weighed against it. A
codex32 set made on the device is counted already (`docs/CODEX32.md`
§9.4). A person who splits a key with Convert has made a backup of it and
wants the plan to say where its parts are and what losing one place costs.

**Decision** (owner, 2026-11-16).

- A Seed XOR set and a SLIP-39 set made on the device can be counted on a
  wallet's backup plan, as a codex32 set is: the plan holds the set as a
  form of the key, linked to it by the key's position in the wallet, and
  the checks count its parts the way they count codex32 strings. Places
  that together hold all n parts of a Seed XOR set, or a quorum of a
  SLIP-39 set, rebuild the key.
- The set actions stay in Convert a seed (F204 stands): Add a share,
  Replace a lost share and Rotate the set for SLIP-39 are not moved to the
  backup.
- Only the set's public facts are kept, never a part or a share. Seed XOR:
  how many parts, all needed, and each part's own master fingerprint.
  SLIP-39: the identifier, the iteration exponent, the group threshold,
  each group's threshold and size, and the member indices made.
- A part is paper only: a plan places it at a place, never in a vault, on
  a stick or as a file. A part counts as checked only once its copy typed
  back here matched.
- One set of a kind per key. A key whose plan already has a set of that
  kind has no second one counted; the way on is that set's own Replace or
  Rotate in Convert.
- The vault's key record keeping these facts with the key, as a codex32
  set's are kept, is a separate change, recorded with the vault's format
  (`docs/VAULT.md` §7).
- A plan with the new forms is read by an older Faraday as a plan it
  cannot read (an unknown line is refused, and so is an unknown thing on
  a spot), never as one without them.
- The spec is `docs/SEED-CONVERSION.md` §1 rule 7.

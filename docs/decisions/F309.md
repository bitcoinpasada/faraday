# F309 Create a vault starts on 64 MiB everywhere, has a 128 MiB preset, and names the Pi in its rows (2026-11-21)

**Kind:** Record
**Status:** Active
**Area:** vaults
**Held by:** tests

*Amends the Create form's starting step, presets and size rows in `docs/VAULT.md` §3.1.*

**Why.** The owner (2026-11-21), on four faults. The form started on 256 MiB even where this computer cannot take it (256 MiB needs 357 MiB free beside the file; a Pi Zero 2 W with 512 MB has about 400 MiB free less what it runs): the step showed chosen and was refused only at Create, with "Choose a cost this computer can allocate". There was no preset between 64 and 256 MiB, so for the 512 MB board Faraday Offline runs on, 128 MiB, the most it opens with room to spare, was reachable only through Custom. The size row "PCs and a Raspberry Pi" did not say which Pi, and a vault made with it on a PC did not open on a Zero 2 W. And the same form started on different steps on different computers.

**Decision** (owner, 2026-11-21).

1. The form starts on Light, 64 MiB at 3 passes, on every computer, in Create and in Backup's flow alike. 64 MiB at 3 passes is RFC 9106's recommendation where 2 GiB cannot be spared and KeePassXC's default; a vault made on a PC opens on every board Faraday runs on, in about 2 s on a Pi 3B+; 64 against 256 MiB is about two bits of a guess's cost, which a passphrase's strength outweighs. Higher steps stay one choice away.
2. A preset of 128 MiB at 3 passes, named Pi Zero, sits between Light and Standard, offered with the others. 128 MiB is one of the file's memory steps.
3. The size rows, in order of memory: PCs and every Raspberry Pi (64 MiB, the default, opens on every machine, the Zero 2 W included), PCs and a Pi Zero 2 W (128 MiB), PCs and a Raspberry Pi 3 (256 MiB) and PCs only (512 MiB). A Pi Zero 2 W is given 128 MiB at most (not half its memory), so ticking it never suggests 256 MiB or more and shows them too large. A size this computer cannot take is still chosen as before and refused at Create.

# F186 One Pi image for every screen, found at boot (2026-11-02)

**Kind:** Record
**Status:** Active
**Area:** release
**Held by:** review

*Amends F145 (2026-11-02): one image per platform, not per screen. Amends F147 (2026-11-02): one Pi image for every Pi and every screen. Amends F150 (2026-11-02): the HDMI screen has no image of its own; HDMI is what the one Pi image starts on when no panel is found. Amends F185 (2026-11-02): the Pi's release files are one, `faraday-pi-VERSION.img.xz`.*

**Why.** A Pi image per screen makes a person know which screen they
have before they download, and makes the release, the Starter and the
download page carry one file per screen, each of which must be built,
tried and kept. Every screen Faraday lists on the Pi has a touch
controller that answers on a bus of its own, so the screen can be found
at boot instead of named on the card; HDMI says what it is through its
EDID. With the Pi's one build (F185) the kernel already carries the
display stack every screen needs. Writing what was found to the card
would break the check of a card against the release (F182), so nothing
is written.

**Decision** (owner, 2026-10-31 and 2026-11-02; `docs/IMAGES.md` §3,
§4, §9).

1. **One Pi image for every Pi and every screen.** The image does not
   name its screen. A boot script, run as root before the app, finds
   the screen: HDMI when its connector reads connected; otherwise the
   first touch controller that answers, the DSI connector's before the
   2.8-inch's on the GPIO header; otherwise HDMI. It loads that
   screen's overlay, kept in the initramfs, through configfs, unmounts
   configfs, and gives the app the screen's values. Nothing is written
   to the card.
2. **Every listed screen is built in at once**: the 2.8-inch DPI, the
   Waveshare 7-inch and 10.1-inch DSI (C), Raspberry Pi Touch Display 2
   and HDMI. A value only a panel can give is the vendor's documented
   one until the panel is tried, and a wrong one fails safe: the screen
   is not set up and the Pi starts on HDMI. A screen not yet tried is
   built, not tried, in the documents and on the website.
3. **The 2.8-inch runs on the kernel's DPI driver**, not the firmware's
   framebuffer; its pins are set up only once its touch controller has
   answered. The ribbon camera stays on the image, beside a USB
   webcam; whether it runs beside each screen, the 2.8-inch on the
   kernel's DPI driver included, is checked on the panel.
4. **One release file**, `faraday-pi-VERSION.img.xz`, in place of the
   per-screen files; the Starter offers one Pi image; each Pi screen's
   tile on the download page leads to it.
5. **Nothing is released from the one image** until the 2.8-inch has
   been tried on it.
6. **The kernel gains run-time overlays** (`OF_OVERLAY`, `OF_CONFIGFS`),
   used by root alone before the app starts.

**Amends** F145 (one image per platform, screen and build), F147 (one Pi
image per screen), F150 (the HDMI screens' one image of their own) and
F185 (the Pi's release files).

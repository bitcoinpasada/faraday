# F245 The Argon QR Vault is built as a test tool outside Faraday's apps (2026-11-11)

**Kind:** Record
**Status:** Active
**Area:** standards
**Held by:** standards.aqrv-out

**Why.** The Argon QR Vault (`docs/AQRV.md`) is Faraday's own
construction and has had no outside review, so STANDARDS §0 keeps it out
of the app. A specification with no code is hard to review and to try: a
reviewer wants a reader to run against the vectors, and a person wants to
see a code made and opened.

**Decision** (owner, 2026-11-11).

1. **A separate tool.** The library, a command line (`aqrv`) and a
   desktop app (Argon QR Vault, for Linux and Windows) live in `aqrv/`.
   They are offered for download as a test tool, from a GitHub release
   with SHA-256 sums, and are not Faraday: no app of Faraday's (the
   stick, the Pi, Faraday Demo, the Starter) depends on any of them, and
   none names them.
2. **Test data.** The tool runs on an online computer, like Faraday
   Demo, and its screens say the format is not reviewed and is for test
   data only. The key boundary (F70) binds Faraday's apps and not the
   tool. The library prints nothing, derives Debug on no secret, and
   wipes what it derives.
3. **Plain code for review.** The library holds the format and nothing
   else. It uses Faraday's Argon2 call, HKDF-Expand and codex32
   checksum, and RustCrypto's ChaCha20, and adds no dependency. Its
   tests run every case of `tools/vectors/aqrv/aqrv.json`.
4. **Into the app only after review.** Bringing the format into Faraday
   is a new decision, made after an outside review is recorded
   (`docs/AUDIT-SUBMISSIONS.md` §10), and the library moves then.
5. **Held by** `tools/lint-standards.toml` (no shipped function under
   `faraday/` reaches the vault's seal or open, and no line names its
   crates), `tools/lint-keys-tests.sh` (no shipped binary depends on
   `aqrv` or turns on faraday-strings' `aqrv` feature) and
   `tools/lint-layout.sh` (no crate under `core/` or `faraday/` depends
   on `aqrv/`).

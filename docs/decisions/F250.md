# F250 Tests fail on a secret left in memory or on a screen (2026-11-12)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** keys.leak-tests, keys.secret-types, keys.leak-entries, keys.stack-and-indexed, keys.leak-allocator-test-only

**Why.** Faraday's secret types wipe what they hold, and `lint-secrets`
keeps heap text out of the files that hold them, but neither says whether
a copy was made anyway: a buffer that grew and left its old block, a
`to_vec` into a type that does not wipe, a string made for the screen.
`docs/SECRET-LEAKS.md` designs the tests that look for the secret itself.

**Decision** (owner, 2026-11-12, the four choices of `docs/SECRET-LEAKS.md`
§9).

1. **A test allocator.** `faraday/tools/leak-scan`, beside
   `faraday/tools/alloc-count`, is a global allocator for test binaries.
   A test arms it with the forms of a test secret; the test fails when a
   freed block, or a block still live after Lock, holds one, naming the
   form and, for a free, where it was freed. The flows under it are in
   `faraday/faraday-core/tests/leaks`: the seed load, sign, show and hide,
   seal, lock, backup and the vault readers. Every freed copy counts, even
   one made and dropped inside one function.
2. **The screens.** The tours fail when the frame after Lock, a hide or
   leaving a page draws a test secret, or a kept image (a sheet's frosted
   copy, a fade's previous frame) holds one
   (`faraday/shells/snapshot/src/leaks.rs`).
3. **The types.** A secret type derives no `Clone`, `PartialEq`, `Debug`
   or `Display`, and `lint-secrets` finds a secret file by the types it
   uses. Clippy's `disallowed-methods` refuses `clone`, `to_string` and
   `to_owned` in the files that hold a secret, by each crate's own
   `clippy.toml` (`faraday-bip`, `faraday-keys`, `faraday-vault`,
   `faraday-pgp`, `faraday-kef`), which repeats `faraday/clippy.toml`'s
   entries; a legitimate copy carries an `expect` with its reason.
   `to_vec` and `String::from` are not refused yet, which
   `docs/SECRET-LEAKS.md`'s Open line says.
4. **Named entries.** A freed copy passes only through an entry in
   `tools/leak-entries.toml` giving its flow, form, place, reason and the
   fix it waits for, added only in a commit that says why and passes
   review, as holds are named (F136). An entry no test hits fails. A copy
   still live after Lock, or a secret still on screen, fails with no way
   through.
5. **Test secrets** are published vectors, long enough that a chance match
   cannot happen; a PIN is looked for only in its own tests.
6. **Review only, no test:** stack temporaries, timing and loads indexed
   by a secret. They are later work under the Security scope.
7. **Nothing shipped.** The allocator is a dev-dependency. This stands
   beside the decision that no shipped program installs a wiping
   allocator (F181) and changes nothing of it.

# F167 Home's Scan takes everything a scanner takes (2026-10-29)

**Kind:** Record
**Status:** Amended by F173
**Area:** keys
**Held by:** keys.home-scan-takes-all

*Amended by F173 (2026-10-29): a TOTP setup code read with no vault open shows the read card, Unlock {vault} or Make a vault, in place of the one line.*

**Why.** Home's Scan is the one press in on the device. It took a seed
and anything that became a file, but it and every other scanner for
anything (Files', Restore's, Create's, the Spend tab's, and the Spend
tab's What do you have?) put a codex32 string, a Codex32QR code or a
SLIP-39 share in Files as a seed part, a TOTP setup code as vault
entries, and a WIF private key, a Nostr secret key or words that fail
their checksum as a note: each a secret in a box, against `docs/QR.md`
§2, none in the flow that takes it, and each refused when pasted.

**Decision** (owner, 2026-10-29).

- Whatever any scanner or form takes by QR, Home's Scan takes too and
  sends where it belongs (`docs/QR.md` §2): a seed (SeedQR,
  CompactSeedQR, words) to Add a key; a codex32 string (a Codex32QR
  code's) or a SLIP-39 share to Add a key's form for it, waiting for
  the rest of its set; a TOTP setup code to a new entry, filled in, in
  the open vault; PSBTs, descriptors, account keys, wallet files,
  signed messages, GPG public keys, BSMS, UR and BBQr transfers and
  Faraday file envelopes to Files and the flow waiting for them; an
  address to its check.
- Where a kind needs something first, the scanner says what in one
  line and stays open: a TOTP setup code with no vault open ("Unlock a
  vault to add it"), a key's part or seed with a stick in (the line
  that asks for it to be pulled). Nothing is filed in its place.
- No scanner files a secret. Files', Restore's, Create's and the Spend
  tab's scanners route a part of a key and a TOTP setup code as Home's
  Scan does; What do you have? sends a part of a key to its form as
  before and names a TOTP setup code ("not used here"). A private key
  (an extended private key, a WIF, a Nostr secret key) and words of a
  BIP-39 list that are no English BIP-39 seed (a checksum that fails,
  an LND aezeed, an Electrum seed) are named on the scanner's line and
  never filed. A file sent in Faraday's envelope is filed as sent.
- What Home's Scan takes pasted on Faraday Demo is what it takes
  scanned (F75): the seed's forms, a codex32 string, a SLIP-39 share
  and a TOTP setup code included.
- Kept elsewhere for a reason: the copy checks (a SeedQR or Codex32QR
  compared with the seed or string open on the backup's item, never
  loaded) take a code only there, since what they read is checked
  against what is on screen and must not load; Transfer's Receive saves
  into Downloads, which Home's Scan does not do; a wallet's Scan a key
  and the codes screen's Scan keep their own scanners, whose code Home's
  Scan routes the same way.
- A new kind a scanner learns is routed from Home's Scan in the same
  change (`keys.home-scan-takes-all`).

# F109 Out of the app until their standards mature: FROST, and MuSig2 signing across places (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** wallets

**Why.** What the app takes in is a published standard, followed and
checked against an implementation Faraday did not write, or Faraday's
own rule that fails closed (`docs/STANDARDS.md` §0). FROST threshold
wallets rest on BIP 445, which is not published, and on a way of signing
across places that is Faraday's own construction and has not been
reviewed: a secret nonce drawn at one place and carried to the next in a
file, or kept in the vault between visits. MuSig2 signing across places
is the same construction: BIP 327 is deployed, but a secret nonce kept
past the session it was drawn in is Faraday's own, and BIP 327 advises
against storing one. There are no users yet, so these leave the app at
once, with no way out kept.

**Decision** (owner, 2026-10-23).

- **The rule.** A feature whose standard is unpublished, or whose
  construction is Faraday's own and unreviewed, stays out of the app
  until its standard is published or it is reviewed. Its code stays in
  the repository, built and tested, compiled out of every shipped app.
  `docs/STANDARDS.md` §0 states the rule and §0.1 lists what it leaves
  out.
- **FROST leaves the app completely**: the Threshold kind, the dealer,
  threshold signing, the carry file, the vault's signing-round record,
  the Learn page and its links, the Tools tile, the Demo's FROST sample,
  the files a test stick carries for it, and the tour's stops. Make a
  new wallet's Threshold kind went in commit 618477cf (codex32's C5-kind
  batch); everything else goes here.
- **MuSig2 signing across places leaves the app the same way.** The app
  keeps no MuSig2 secret nonce past the session it was drawn in: a
  round that goes first holds its nonce in memory for that one
  transaction, and a lock or a power-off ends it. Rounds sealed into the
  vault across a lock are not offered. MuSig2 with the session kept open
  between the rounds, and signing last by BIP 327's `DeterministicSign`,
  stay.
- **One switch.** The app's FROST code is behind one cargo feature,
  `unreleased`, off by default: faraday-core's turns on the same feature
  in `faraday-keys`, `faraday-learn` and `faraday-strings`, and the
  Demo's samples (`faraday-samples`), the test kit's tool and the
  snapshot tours have their own, which turn on faraday-core's. No
  shipped binary turns it on; `tools/lint-keys-tests.sh` fails if one
  does. Without it a threshold record is not read as a wallet
  (`faraday_core::wallet::read_wallet`), a carry file is a file Faraday
  does not read, a 24-word key is no FROST share, `faraday-keys` deals
  no group (`Keys::deal`, `Keys::add_dealt`), and the strings, the
  Learn page and the guide text only FROST used are not in the build.
- **The core stays.** `core/faraday-bip`'s FROST arithmetic and threshold
  record, `core/faraday-psbt`'s threshold signing, their tests, vectors
  and F79 cross-check area are unchanged and built and tested by `just`
  as before. `just` also runs clippy over the workspace and the tests of
  the crates that have the switch with `unreleased` turned on, so the
  app's FROST code keeps building and passing while it is out.
- **The vault is unchanged.** Record type 9 keeps its number and layout
  in `faraday-vault`; an app built without `unreleased` writes none and
  reads none into a spend.
- **Coming back** is the owner's decision, recorded here or in a decision
  that amends this one: FROST when BIP 445 is published and signing
  across places has been reviewed; MuSig2 rounds across places when
  that construction has been reviewed.

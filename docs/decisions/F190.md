# F190 The vault is a KDBX 4 file under Argon2id, and the QR vault an RFC 9580 OpenPGP message under Argon2id (2026-11-02)

**Kind:** Record
**Status:** Amended by F193 and F194
**Area:** security
**Held by:** review

*Amends F97 (2026-11-02): the KeePass export is folded into the vault (point 10). Amends F189 (2026-11-02): points 1, 3, 5, 6 (the QR vault's file), 7, 9 and 10 (the reader) are replaced by this decision; points 2, 4, 6 (what a QR vault holds and how it is used) and 8 are kept, as point 9 below says. Amends F160 (2026-11-02): the F79 area `vault` checks the vault against pykeepass, `keepassxc-cli` and Sequoia's `sq`, in place of Go `age`.*
*Amended by F194 (2026-11-03): point 3 no longer refuses a file for a damaged item; it is Unreadable, and TOTP is read from every form in use.*
*Amended by F193 (2026-11-03): point 11's keepass-rs and rPGP judge the file format only; pykeepass, `keepassxc-cli` and Debian's `sq` judge the primitives; OpenPGP.js waits for Node.*

**Why.** F189 made the vault an age file so that it opens without
Faraday, but age's one passphrase type is scrypt, and the owner prefers
Argon2id (RFC 9106). Two published formats store Argon2id's parameters
with the ciphertext and are read by programs Faraday's authors did not
write. KDBX 4 (KeePass) is a password database: KeePassXC, KeePass,
KeePassDX, Strongbox and pykeepass open it, and its entries are what a
person already keeps passwords in. Its smallest file holding a 24-word
seed is about 1,140 bytes, QR version 28 at medium error correction,
against version 15 for age. RFC 9580 OpenPGP (Proposed Standard) encrypts
a message under a passphrase with Argon2id (its Argon2 S2K) and AEAD; a
QR vault in it is about 396 bytes, version 15, and Sequoia (`sq`),
GopenPGP, OpenPGP.js and rPGP read it. GnuPG does not: it follows
LibrePGP, not RFC 9580. So each size takes the format that suits it:
KDBX for the vault a person keeps, OpenPGP for the one printed as a code.
Faraday already writes both: KDBX 4 for KeePass (F97, `docs/KDBX.md`)
and its own OpenPGP packets, only the part used (F178).

**Decision** (owner, 2026-11-02; `docs/VAULT.md`).

1. **A file vault is a KDBX 4 database** (KeePass's specification,
   pinned in `tools/reference/kdbx4/`), read and written as it says.
   Faraday writes version 4.0: ChaCha20, Argon2id 1.3, no compression,
   the passphrase alone as the composite key (no key file), `.kdbx`. A
   file is a vault by its contents (KDBX 4's signatures and version),
   whatever its name.
2. **Saved by another program, it opens within limits** (owner,
   2026-11-02). A KDBX 4.0 or 4.1 file a KeePass app saved opens:
   ChaCha20 or AES-256, Argon2id or Argon2d, gzip or none, under the
   cost limits of `docs/VAULT.md` §3. What KeePass apps keep that
   Faraday does not read (attachments, icons, times, tags, AutoType, groups' settings, other
   programs' custom data) are carried through unchanged (owner,
   2026-11-02): Faraday keeps what it does not read as it was and writes
   it back where it was. Entry history and the recycle bin are dropped,
   being old or deleted copies of secrets, and the unlock names them
   before the vault opens. KDBX 3.1, AES-KDF
   and Twofish are refused, naming them. A key file and a
   challenge-response key cannot be named (owner, 2026-11-02): KDBX 4
   records nothing that shows either, so a file that needs one is
   indistinguishable from a wrong passphrase, and the wrong-passphrase
   message for a KeePass file says that a file which also needs a key
   file or a security key cannot be opened here (`docs/VAULT.md` §7.1). Faraday's next seal writes the file in its own form (point 1).
3. **Each item is a KeePass entry** (owner, 2026-11-02): an entry a person
   keeps (title, username, password, URL, notes, an `otp` field with an
   `otpauth://` URI, as KeePassXC writes it, and any other fields, kept
   as written) is an ordinary entry; a seed, wallet, note, recovery
   sheet, GPG key, Secure Boot set, wallet share, passphrase or codex32
   share is an entry in its kind's group, its secret in a protected
   field and its other values in fields named as F189's TOML keys were,
   and its kind and Faraday's facts about it in the entry's custom data.
   Faraday's bookkeeping (the seal count, signed amounts, backup plans)
   is in the database's custom data; the vault identifier is the root
   group's UUID, KDBX's own (owner, 2026-11-02). A seed's codex32 set
   and BIP-85 origin are saved with it unless the person unticks them
   when saving, and can be removed from an open vault (owner,
   2026-11-02). Custom data
   is part of KDBX 4, inside the encryption: any KDBX reader with the
   passphrase reads it, KeePassXC keeps it when it saves, and its views
   do not show it. Which names mean what is Faraday's own rule, in
   `docs/VAULT.md` §7, and fails closed for Faraday's items: an unknown
   kind, a malformed value or a field its kind does not name refuses
   the file, naming the entry.
4. **The four file sizes are kept** (owner, 2026-11-02, as long as the
   file still opens in other KDBX programs): Faraday pads the document
   with line feeds after its closing tag, which XML allows and every
   KeePass app reads. A KeePass app's save drops the padding (KeePassXC
   pads in its own way), so such a file's length says more until
   Faraday seals it again.
5. **A QR vault is an RFC 9580 OpenPGP message under a passphrase**:
   one version 6 symmetric-key encrypted session key packet with the
   Argon2 S2K, then one version 2 symmetrically encrypted and integrity
   protected data packet, AES-256 in OCB mode (the RFC's mandatory AEAD),
   holding one literal data packet. The literal data is F189's QR TOML,
   unchanged: the item's keys at the top, padded to 226 bytes. The file
   is about 396 bytes, QR version 15 (77 × 77) at medium error
   correction. Faraday writes it binary, `.pgp`; it reads the binary form
   only and refuses any other packet sequence, naming it.
6. **Argon2id's memory takes F189's five steps**, 64 MiB to 1 GiB, 256 MiB
   the default, with 3 passes and 4 lanes in both formats, RFC 9580's
   second recommended choice at its memory raised to the step. Each step
   adds ≈ log2(memory in KiB × passes) bits: ≈17.6 to ≈21.6. Readers
   refuse a cost above their limits (`docs/VAULT.md` §3) before they
   allocate.
7. **The passphrase is put in Unicode NFC**, as F159 point 2 says, and
   its UTF-8 bytes are the KDBX password and the OpenPGP passphrase.
   Neither KeePass apps nor `sq` normalise; the vectors show a vault
   whose passphrase has two forms opening under its NFC form.
8. **Every seal is a new file**: a new master seed, IV, Argon2 salt and
   inner stream key for KDBX, a new salt, IV, session key and data salt
   for OpenPGP, from one `fresh_bytes` call each (F189 point 8 kept).
   The seal count is in custom data (point 3), and an older copy is
   named at unlock as F189 point 7 says.
9. **What F189 keeps.** The passphrase in NFC (point 2), the five sizes
   (point 4: QR and four file sizes, now padded as point 4 above says),
   what a QR vault holds and how it is made, changed, scanned and
   offered (point 6, with `.pgp` for `.age`), and the session's
   randomness for every seal (point 8). FVLT stays removed (point 10).
10. **The KeePass export is folded into the vault** (owner, 2026-11-02):
    one KDBX writer and one shape. Giving a KeePass app one key, note,
    sheet or entry is making a vault that holds it. `docs/KDBX.md`'s
    export, its strings and its vectors go when the vault is built.
11. **Written here, only the part used** (F178). KDBX: the header, the
    HMAC block stream, ChaCha20 and AES-256-CBC, gzip read, the inner
    stream, and an XML reader that refuses a DOCTYPE and any entity it
    does not define, over vetted crates. OpenPGP: the two packets and
    the literal data packet, in `faraday-pgp` beside the key's, over
    Faraday's Argon2id and HKDF and vetted AES and OCB. The established
    format crates were weighed and not taken (owner, 2026-11-02):
    `keepass` (keepass-rs) drops XML elements it does not model, which
    point 2 forbids, and draws a save's randomness itself, which point 8
    forbids; rPGP (`pgp`) is audited but brings every OpenPGP algorithm
    with it, 61 required crates for a message that uses AES and OCB.
    Both are used in the tests as outside readers and writers, never in
    what ships. Checked in the F79 area `vault` against pykeepass,
    `keepassxc-cli` and keepass-rs for KDBX, and against Sequoia
    (`sq`, pysequoia), OpenPGP.js and rPGP for OpenPGP, both ways: each
    opens the files the other made. The age codec F189 point 9 wrote
    goes.

**Not done.** The first half of Argon2id's first pass reads memory
independently of the passphrase (the id variant's point), but the rest
reads it at places the passphrase decides, a cache-timing side channel on the computer that unlocks; later
work under the Security scope, as wiping freed copies is.

**Amends** F189 (points 1, 3, 5, the QR file of 6, 7, 9 and 10's
reader), F97 (the KeePass export is the vault, point 10) and F160 (what
the vault area checks against).

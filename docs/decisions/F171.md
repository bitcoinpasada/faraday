# F171 A WIF private key is swept, never kept: a sheet of its addresses, its PSBT reviewed against the loaded wallets and signed with a hold (2026-10-29)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** tests

**Why.** A paper wallet, an old `dumpprivkey` or an exchange's export
holds one private key written as WIF. INTEROP §5 I11 planned to load such
a key as a key and a wallet of one address, and to keep it in a vault as
a single-key record. That record is no format Faraday has, and a key
with no BIP-32 master fits none of what a loaded key is: it has no
master fingerprint, no words, no SeedQR and no shares, so Wallets,
Backup, Explore and the key slots would each need a case of their own.
What a person does with such a key is move its coins to a wallet that is
backed up.

**Decision** (owner, 2026-10-29: the WIF is swept and never kept; the
sheet names the key by an address and shows its legacy, SegWit and nested
SegWit addresses as QR codes; an online watch-only wallet builds the PSBT;
Faraday signs after showing that every output goes to a loaded wallet,
others flagged; the key lives in memory only, wiped at Done, a lock or
leaving; Backup offers nothing; Faraday Demo takes test-network keys and
paste on the Sweep scanner, mainnet refused; Home's Scan routes a WIF to
the sheet. `docs/INTEROP.md` §5 I11). Faraday's rules for it:

1. **Sweep only.** A WIF is never loaded as a key and never kept: no
   vault record, no key slot, no change to Wallets, Backup or Explore.
   Backup offers it nothing; the sheet says the key is not kept.
2. **The Sweep sheet** is drawn as Faraday's other sheets are, a
   Material dialog (DESIGN §4.13). A WIF typed on it (Tools, **Sweep a
   private key**) or scanned (its own scanner, or Home's Scan) opens it
   on the key, named by its legacy address, which every WIF pays and a
   paper wallet prints, with the addresses it pays, each with its QR
   code: legacy, native SegWit and nested SegWit for a compressed key,
   legacy alone for an uncompressed one. Every other scanner refuses a
   WIF and files nothing.
3. **The PSBT.** The sheet's scanner reads the sweep's PSBT. The review
   shows the key's inputs, the inputs of other keys (not signed), and
   each output with the loaded wallet whose address it is among its
   first hundred on each chain. An output to none of them is flagged on
   the review and not refused: the hold signs past it. The hold signs
   the key's inputs; the signed PSBT, and the finished transaction when
   every input is signed, go to the Outbox.
4. **The key** lives in memory only, in the session's key store
   (`faraday-keys`, F70), and is erased at **Done**, a lock, or leaving
   the sheet. It leaves only as signatures: no reveal is added.
5. **Faraday Demo** takes test-network WIF keys, pasted too on the
   Sweep sheet's scanner (F75); a mainnet key is refused, as a test
   network's is on Mainnet. Practice sweeps none: it takes only its
   samples (`docs/DEMO.md` §2).
6. **With it**, a legacy input whose script code holds
   `OP_CODESEPARATOR` is refused in every signing, before anything is
   signed ("A legacy input with OP_CODESEPARATOR is not signed"; owner,
   2026-10-24, INTEROP §5 I11).

**Not taken:** a WIF loaded as a key with a single-address wallet; a
single-key vault record. Not swept: a Taproot address of the key, and a
descriptor with a private key inside (`wpkh(L…)`).

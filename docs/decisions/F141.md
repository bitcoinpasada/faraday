# F141 A miniscript or a taproot tree of one key is signed only through its registered wallet (2026-10-27)

**Kind:** Record
**Status:** Active
**Area:** wallets

**Why.** F135 holds a script of several keys to a registered wallet and
leaves a script of one key alone. Signing and inspection then answered
differently for the same input: a taproot leaf of one key, or a `wsh`
miniscript of one, that no registered wallet gives was signed whenever
another input of the PSBT took part, while inspection did not count the
person's key as taking part in it, so the same input alone was refused
(`NoParticipatingKey`). Whose such an input is, and what it can be spent
by, is the coordinator's word alone until a wallet says so, and what
cannot be verified is refused, not assumed. Ledger signs a script only
for a registered wallet policy, Coldcard only for a registered
miniscript or tapscript wallet.

**Decision** (owner, 2026-10-27; `core/faraday-psbt/README.md`,
`docs/WALLETS.md` §3.3, `docs/FLOWS.md` Spend tab):

1. **The rule.** A miniscript (P2WSH or P2SH-P2WSH) or a taproot tree
   input (a leaf, or the key path of an output that states a tree) is
   signed only through a registered wallet that holds a loaded key and
   gives its script at the chain and index the input states, whatever
   the number of its keys. Inspection counts a loaded key as taking part
   in such an input only through that wallet (`InputInfo::is_ours`), and
   `faraday_psbt::sign` signs it only where inspection does: one rule,
   in one place (`signed_through_wallet`).
2. **Left unsigned, and said so.** An input that names a loaded key in
   such a script of one key, with no wallet that gives it, is not signed
   and does not hold the spend up: it is left unsigned, the rest of the
   transaction is signed, and Review names it, a caution
   (`NoWalletForScript`): "Input 1 is left unsigned: no registered
   wallet covers this taproot tree. Register its wallet to sign it." (or
   "this script" for a miniscript). Like change that cannot be verified
   (F136 §5), it is shown for what it is, not trusted.
3. **Nothing taking part.** Where no input takes part, the PSBT is
   refused with `NoParticipatingKey`, as before (F136 §3).
4. **Unchanged.** A script of several keys stays blocked without its
   wallet (F135 §1). A single-key wallet's own input (BIP 44, 49, 84,
   86), a BIP-86 key path with no tree and MuSig2 are not trees and are
   signed as before.
5. **The cross-check** (F79) signs such an input in its reference only
   through a registered wallet whose script it is, and its corpus
   registers the wallet of half its taproot trees, so their signatures
   are still compared.

**Amends.** F135 (a script of one key, held to its wallet too) and F136
(an input left unsigned is a caution on Review, not a stop).

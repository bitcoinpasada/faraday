# F325 Work kept out of the app may also be held by a build switch that only Faraday Demo's dev build turns on (2026-11-23)

**Kind:** Record
**Status:** Active
**Area:** standards
**Held by:** standards.out-of-app

*Not built.*

*Amends F234: work kept out of the app is no longer held by reachability alone.*

**Why.** The owner wants a feature finished and tried in full (screens,
strings, guide) before it is offered, and then offered by one short
change. Screens that nothing reaches cannot be tried.

**Decision** (owner, 2026-11-23).

1. **A cargo feature for each such work**, off by default. With it off, its
   crate, screens and actions are not compiled into a binary.
2. **Only Faraday Demo's dev build turns one on** (F326). No image, no
   Starter, no Demo of a release and no dev build of the app does. Nothing
   on a device or in an app's settings turns one on.
3. **Held in three ways:** a lint refuses the feature in a shipped build,
   the release build refuses it, and the finished binary is checked for
   the crate.
4. **Both states are checked**, with the feature off and with it on.
5. **The features are** `handwriting` (reading handwritten words) and `ace`
   (F327). Another is a decision.
6. **Turning one on in the app is a decision of its own**, on the owner's
   word. STANDARDS §0 still says what may enter.
7. **F234's rule stays** for all other work kept out of the app: no shipped
   code reaches it. Its check (`tools/lint-standards.py`, check 2) also
   covers these features: with a feature off, no shipped function reaches
   what it holds out, and code compiled only with it on is not counted as
   shipped. The change that adds the first feature changes the check.

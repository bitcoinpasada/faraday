# F180 The review of 2026-10-31: getrandom trusted, two libraries used as not established, HKDF and the BIP-39 core kept, A1 through libsecp256k1, a FAT32 formatter of Faraday's own (2026-10-31)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** crypto.established

**Why.** A review of the tree on 2026-10-31 (`docs/ESTABLISHED.md`)
found pieces Faraday writes that F178's list did not name, places
where a secret's value steers time or leaves copies that F178's three
timing fixes did not cover, and facts that change two of F178's
switches: hkdf 0.13.0 leaves the pseudorandom key and each output block
unwiped, which Faraday's own code wipes, and the bip39 crate's word
lookup takes a time that depends on the word, which a constant-time
lookup of Faraday's own does not. Three libraries the manifest names
are not established by F178's test.

**Decision** (owner, 2026-10-31; `docs/ESTABLISHED.md`). It amends
F178 and F71.

1. **getrandom** is trusted under F71 for its publisher
   `github:rust-random/getrandom`, from 2025-12-27 (ESTABLISHED §2.2);
   version 0.3.4, on winit's path, stays an exemption.
2. **lzma-rust2 and rqrr** are used as not established, each with a
   `[[not_established]]` entry and the reason ESTABLISHED §2.2 gives:
   lzma-rust2 is the one pure-Rust streaming xz decoder, STARTER §1.3
   rules out the C library, and what it decodes is checked against the
   signed manifest's SHA-256; rqrr is vendored and patched, the one
   maintained pure-Rust QR decoder, and what it decodes is untrusted
   input Faraday's parsers check. Its panic fixes are offered upstream.
3. **HKDF** stays Faraday's own, for the reason that hkdf 0.13.0 does
   not fit the key rules: it leaves the pseudorandom key and each T(i)
   unwiped. A change that wipes them is proposed to RustCrypto, and the
   switch is checked again when a release carries it (ESTABLISHED
   §6.7). F178's trust entry for hkdf is not written.
4. **The BIP-39 core** stays Faraday's own, made constant time
   (ESTABLISHED §4.5), for the reason that the bip39 crate does not fit
   the key rules: its word lookup and bit packing take a time that
   depends on the words. The crate stays the implementation Faraday's
   tests compare against (ESTABLISHED §6.9). F178's trust entry for its
   publisher is not written.
5. **The scalar arithmetic on secrets** is libsecp256k1's, as F178
   says (ESTABLISHED §4.1): a secret passed as a `Scalar` is only handed
   to the library, never compared; `SecretKey`s are kept in short
   scopes; rust-secp256k1 0.29.1's `SecretKey` is `Copy`, so wiping
   reaches the last copy only.
6. **A FAT32 formatter** for the Starter's data partition is written
   here, for the reason that no established implementation exists,
   tested against dosfstools' `mkfs.fat` and `fsck.fat`; faraday-fat's
   rule becomes that the Starter formats the data partition and nothing
   else formats a partition. The `written_here` count rises by one when
   it lands (ESTABLISHED §3.2, batch E1).
7. The pieces ESTABLISHED §3 adds, with this decision in their
   decision column, are accepted under it.
8. The cross-check's outside implementations are chosen after the
   app's own switches are fixed, since a library the app uses cannot be
   its own cross-check (ESTABLISHED §9).

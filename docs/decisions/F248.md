# F248 A Rust file has no line limit; code is split by function (2026-11-12)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** structure.size

*Replaces F196's size rule (its points 1 and 2): a `.rs` file may be any length, and `lint-tree`'s 2 MiB limit on a file is the only bound. F196's points 3 and 4 stand.*

**Why.** The limit split code by length, not by where it belongs: the
last split of `lib.rs` moved unrelated area code only to get under it.
The structure is held by function instead: the code map, the list of
files allowed an `impl Faraday`, `Faraday`'s field count, an area's
folder, and the lint that keeps `core/` from depending on `faraday/`.

**Decision** (owner, 2026-11-12; `docs/STRUCTURE-PASS.md` §7.2).

1. **A `.rs` file has no line limit.** `lint-layout` no longer counts a
   file's lines and `tools/lint-layout.counts` lists none. Code is split
   by what it does, never by how long it is.
2. **Clippy's limit on a function stays:** a function over 100 lines
   carries `#[expect(clippy::too_many_lines, reason = "...")]`
   (`structure.size`).
3. **What stays:** `lint-tree`'s limit of 2 MiB on a file, and the
   structural rules of F74 and F196's points 3 and 4.

# F177 Each Cryptography block says whose specification, whose implementation and whose check an action rests on, each own or outside (2026-10-30)

**Kind:** Record
**Status:** Amended by F179
**Area:** crypto
**Held by:** crypto.independence-labelled, crypto.independence-said

*Amended by F179 (2026-10-30): point 1 in other words: a block's fields are Specification and Code, the Code field's lines "Library: …" and "Faraday's code: …"; "implementation" names only a cross-check's second program, compared as others' code or Faraday's second version.*

**Why.** F160 made each action say who wrote its cross-check's
reference, in words of its own: an "own construction, not yet
independently reviewed", a reference "own-over-outside" or "own-only",
"not an independent check", "Reference written outside Faraday". A
reader of a block had to learn those words to tell what the action
rests on, and "not an independent check" read as a check of no value.
A check against a second implementation Faraday's authors wrote, in
another language, from the specification, catches a slip between the
two implementations; what it cannot catch is a misreading of the
specification both share.

**Decision** (owner, 2026-10-30). It amends F160 points 2 and 3, their
words and classes only; F160's points 1 and 4 to 8 stand.

1. **Two words, each own or outside.** What a reader sees of an
   action names its **specification** and its **implementation**, each
   **own** (Faraday's authors wrote it) or **outside** (others did).
   "Model", "own construction", "own-over-outside", "own-only", "not an
   independent check", "Reference written by" and "Reference written
   outside Faraday" are not used. A check against a second implementation Faraday's
   authors wrote is said to be not checked against an outside source,
   never "not independent".
2. **The cross-check's classes** (`docs/crypto/actions.toml`,
   `schema = 4`): `independence.class` is `outside` (compared with an
   implementation others wrote), `outside-and-own` (compared with an
   outside implementation, and, for a part, with one Faraday's authors
   wrote) or `own` (compared only with an implementation Faraday's
   authors wrote). `author` names the outside implementation, for the
   first two; `ours` names the part Faraday's authors wrote, for the
   last two.
3. **The label.** An action whose specification is Faraday's own (the
   actions F160 point 3 lists) carries the label "own specification,
   not yet reviewed outside Faraday", and where the block draws it, the
   line under it says what ends it: an outside review recorded in a
   decision; a reproduction from the specification by an outside party
   is asked for in `docs/AUDIT-SUBMISSIONS.md` §10. What counts as that
   review, and who reviews, stay as F160 point 3 has them.
4. **Libraries and vectors say whose they are.** Each library an action
   names states its author once, in a `[library.<name>]` table, read
   from the crate's own metadata; each vector folder an action names
   says whether it is published, and by whom, computed by an outside
   implementation, or Faraday's own known answers, in a
   `[vector.<folder>]` table. `docs/crypto/check.py` fails a named
   library or folder with no table.
5. **Matched behaviour is said as behaviour.** Where Faraday does what
   another program does, the text says so ("Low-R grinding, as Bitcoin
   Core does it"), never in words that read as code taken from it.

**Where:** `docs/STANDARDS.md` §0; `docs/CROSSCHECK.md` §10.6;
`docs/CRYPTO-LEARN.md` §1, §2.2, §10.3, §11; `docs/crypto/actions.toml`,
`check.py`, `verified.py`, `gen.py`, `gen_how.py`;
`faraday/faraday-learn/src/how.rs`; `tools/crosscheck/README.md`.

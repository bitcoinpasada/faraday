# F90 Where Faraday refuses input its standard allows (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** crypto

**Why.** CLAUDE.md: accepting more than a standard requires is the
owner's decision, recorded here; so is refusing what a standard allows.
Each refusal below is input a standard permits and Faraday does not
take, kept so that a file or a share cannot ask for work or a result
Faraday cannot check.

**Decision** (owner, 2026-10-23).

- SLIP-39 shares with an iteration exponent above 5 are refused
  (`MAX_READ_ITERATION_EXPONENT`, `core/faraday-bip/src/slip39.rs`). No
  known wallet writes above 1, and the published vectors use 0, 2 and
  3. Exponent 15, which the field allows, is close to an hour on a Pi 3
  and reachable from a file with no press.
- A SLIP-39 split with a group threshold of 1 over several groups is
  refused.
- codex32 recovers a secret only from exactly k shares, and derives a
  further share only from exactly k strings, at an index not already in
  use (`core/faraday-bip/src/codex32/mod.rs`).
- All are kept: they fail closed. Each is revisited if a real set is
  refused.

# F84 Check a signer fails closed; unknown fields are findings there and Info in a review (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** review

**Why.** A signing device is given a PSBT and returns one. What it may
change is small: it adds signatures, or finalizes an input from them.
Anything else it writes reaches the coordinator and the chain, and can
carry data out (a key, in a field or a nonce) or change what is spent.
Faraday holds every check in `core/faraday-psbt`, and no screen used
them. A pass that passes what it could not check tells a person a
device is honest when nothing showed it.

**Decision** (owner, 2026-10-23; the spec is `docs/SIGNER-CHECK.md`,
planned).

- A Tools flow, **Check a signer**, compares the PSBT sent with the PSBT
  returned and states a verdict.
- The verdict fails closed. Clean means only: signatures added under
  keys the sent PSBT names with an origin, that verify under the
  sighash the input asks for; inputs finalized where Faraday's own
  finalizer, given those signatures, writes the same final fields; the
  fields a finalizer clears, cleared; MuSig2 nonces and partial
  signatures (BIP-373) for named participants. Anything else is a
  finding. A signature not checked is never clean. A signature under a
  key the sent PSBT did not name is a finding.
- Unknown and proprietary pairs: in the signer check, each pair that
  appeared or changed is a finding of its own, named by its key type
  and sizes, never by its content. In the review of a single PSBT, the
  pairs this crate does not read are one Info line with their count.
- A field or signature removed, and a signature not checked, are
  Caution; added or changed is Danger; all fail the verdict. A clean
  verdict does not need nonces recomputed: the count recomputed is
  stated. A MuSig2 nonce added is Info.
- The flow opens from Tools and from a PSBT row's ⋮ in Files; Practice
  carries a sample pair. A finished transaction returned in place of a
  PSBT is not read.

# F253 A function has no line limit; a cognitive-complexity ceiling and a review keep it to one job (2026-11-14)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** structure.size, structure.one-job

*Replaces F248's point 2 (clippy's 100-line limit on a function). F248's points 1 and 3 stand.*

**Why.** The 100-line limit split code by length, as F196's file limit
did: a function that does one thing and takes 150 lines to do it (a
test that walks one scenario, a dispatch with an arm for each case)
carried an `#[expect]` and a reason nobody read, and 169 of the 176
markers still named a lint that counted them no longer. What keeps a
function from becoming several jobs is how tangled it is, not how long.

**Decision** (owner, 2026-11-14; `docs/STRUCTURE-PASS.md` §7.2).

1. **A function has no line limit.** Clippy's `too_many_lines` is off
   and its 176 markers are gone.
2. **Clippy's `cognitive_complexity` is on** for every crate, at 40
   (`core/clippy.toml`, `faraday/clippy.toml`, and each crate's own
   `clippy.toml`, which shadows them). It counts branching and nesting,
   so a long straight function scores low and a short one doing several
   jobs scores high. A function over it carries
   `#[expect(clippy::cognitive_complexity, reason = "...")]`; `lint-layout`
   checks that each marker has a reason. Eleven functions carried one when
   it was set (clippy's default of 25 would have named 47).
3. **A reviewer reads what the number cannot** (`structure.one-job`): a
   change that adds such a marker, or grows a function a second job, is
   reviewed and attested with `Reviewed: structure.one-job`.
4. **The threshold only falls.** Raising it is the owner's decision,
   recorded here.

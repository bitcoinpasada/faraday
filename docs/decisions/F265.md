# F265 A push to main whose head commit already passed the check (run by hand on a branch) runs nothing again; the caches are still saved by main when a manifest changed (2026-11-14)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** repo.ci-check

*Amends F183 (2026-11-14): its token may also read the list of workflow runs and caches, in the one first job below; everything else F183 says holds. F212 (caches written only by a push to main) holds unchanged.*

**Why.** The push train checks its tip as `check` started by hand on a
branch, then fast-forwards main to that same commit; the push started the
whole check again on the same commit, about eight minutes with nothing new
to learn.

**Decision** (owner, 2026-11-14).

1. **A first job, `gate`,** runs on a push to main (on nothing else it
   does anything). It asks the API, with the read-only token (`permissions:
   contents: read, actions: read`, on that job only), for a run of `check.yml`
   on the same head commit that ended `success` and is not this run.
   It writes the run it relies on into its log and the run's summary.
2. **A pass found, the check's jobs do nothing,** tests, doc tests and
   lints alike. Only a second job, `warm`, runs, and only on a push to main:
   for each dependency cache main lacks for the commit's manifests and lock
   files (the keys of F212 point 4, and the tools cache's key), `gate` lists
   the job that saves it, and `warm` compiles just that job's dependencies
   with the job's own compile command and saves them (F212 point 2), running
   no test or lint: `cargo nextest archive` for the tests and the touch-target
   run, `cargo test --doc -- --list` for the doc tests (cargo refuses `--doc` with `--no-run`), `cargo check` for
   clippy (a dependency is built by plain rustc there), `cargo build` of the
   one crate for the repository lint and for the instruction counts, and
   nothing for the dependency lint, whose `target/` holds no compiled
   dependency. A cache that is there starts no job. The tools cache is saved
   by the repository lint's warm job when it alone is missing. No pass found:
   the whole check runs as before.
3. **The result is still one.** `check` passes only when `gate` passed
   and every other job passed or was skipped by `gate`.
4. **A commit, not a tree.** The pass is looked up by head commit, which
   a fast-forward keeps; a rebuilt commit with the same tree runs the
   check. Nothing else changes: pull requests and runs by hand run the whole
   check, uses no secret, and writes nothing.
5. **The warm commands run before main.** The commands
   of point 2 are in `tools/warm-compile.sh`, which `warm` calls. Every run
   by hand also runs them in a job `warm-commands`, one per job, saving
   nothing, so a command cargo refuses fails the push train's check and
   not main's. The input `warm_commands` (default true) leaves it out.

# F183 The check runs on GitHub Actions: `just` on every push to main and every pull request, read-only, building nothing for release (2026-10-31)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** repo.ci-check

**Why.** The check ran only where someone ran it. A pull request
arrived with no result beside it, and nothing showed that a commit on
main still passed on a fresh machine with only the tools
`docs/DEVELOPING.md` names. GitHub runs Actions on its own runners at
no charge for a public repository.

**Decision** (owner, 2026-10-31). It replaces the rule in `CLAUDE.md`
"No hosted CI, no GitHub Actions"; "no metered external services"
stays.

1. **One workflow**, `.github/workflows/check.yml`, runs `just` on
   GitHub's Linux runner on every push to main, every pull request, and
   when started by hand. It installs the tools DEVELOPING §1 names for
   the check, at fixed versions, and nothing else. It passes when `just`
   passes: the check stays `just`, and a clone without GitHub checks the
   same way.
2. **It only reads.** Its token can read the repository and nothing
   more; it uses no secrets and no `pull_request_target`; the checkout
   keeps no credentials; it uses only GitHub's own actions
   (`actions/*`), each pinned by its commit. Its cache holds downloaded
   crates and the installed tools, never build output.
3. **It builds nothing for release.** No image, no app for publishing,
   no release, no signature. Building a release on GitHub is a decision
   of its own; one that makes it puts the owner's signature only on a
   release rebuilt elsewhere and found identical.
4. **GitHub's standard runners only**, free for a public repository; no
   larger runner, which is metered.

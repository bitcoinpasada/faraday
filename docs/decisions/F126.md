# F126 Faraday Demo runs inside Faraday Starter; one theme in a session (2026-10-26)

**Kind:** Record
**Status:** Active
**Area:** Starter
**Held by:** tests

**Why.** Faraday Demo was a second program the Starter carried as a
payload file, unpacked into a cache, installed beside itself with a
menu entry of its own, and started as a process apart (F83). A person
had two windows and two menu entries for one download, the Demo did not
end with the Starter, and a theme chosen in one was not the other's.

**Decision** (owner, 2026-10-25).

- Faraday Demo is compiled into the Starter. **Open Faraday Demo** on
  Home shows it in the Starter's own window, under the Starter's top
  app bar titled "Faraday Demo", with its host's strip and its app as
  in its own window (`docs/DESKTOP-HOST.md`); the bar's way back, the
  window's close button and the Demo's power off return to Home. Each
  open is a fresh session in Practice; its stick folders are
  `~/faraday-sticks`, and its Transfer the Starter's Downloads. The
  macOS Starter offers none (F83).
- The Starter no longer carries Faraday Demo as a payload file, installs
  it, or starts it as a process. Install, update and Uninstall remove a
  Faraday Demo an earlier Starter installed (`faraday-demo`, and the
  older `faraday-desktop`, with their menu entries or shortcuts) and the
  cache it ran from, only when the file answers `--version` as Faraday's
  desktop app; somebody else's file of that name stays. Staging a
  release takes no Faraday Demo build, and the payload holds the images
  alone.
- One theme in a Starter session: the Demo opens in the Starter's
  theme, and a theme chosen in the Demo is the Starter's from then on,
  kept when the Demo is left, in memory only. Nothing is stored across
  starts and there is no settings file. At each start the Starter is in
  Cobalt at Standard contrast, Light or Dark as the operating system's
  own setting asks apps (Windows' app mode, the XDG desktop portal's
  `color-scheme` on Linux and, where no portal answers, GNOME's), and
  Light when the setting says neither or cannot be read.
- The Starter binary now holds Faraday Demo's shell side
  (`faraday-desktop`) and through it the public samples Practice takes
  (`faraday-samples`). Both are public data and code the Starter's
  Transfer and Learn already ran beside: the Starter linked
  `faraday-core` and `faraday-keys` before, so no key path is new to
  it, and key material still lives in `faraday-keys` and leaves only
  through its named reveals (`docs/KEYS.md`). `tools/lint-keys-tests.sh`
  lets the Starter reach `faraday-samples`, through `faraday-desktop`
  alone, beside the desktop app; the stick, the Pi, the disk and grant
  helpers, the boot report and the Starter's own crate still may not.
- The `faraday-desktop` package and its `faraday` binary stay, for
  developers (`cargo run -p faraday-desktop`); its window and the
  Starter's share `faraday_desktop::Demo`.

**Amends.** F83 (the payload file, Install and the separate start), F16
and F119 (the installed `faraday-demo`, `Faraday Demo.exe` and their
menu entries, and the `faraday-demo-…` payload files), and F113 (the
Starter's mode at start follows the operating system).

# F192 The cross-check's outside sources: another lineage, Faraday's second version kept only where none covers it, every judge required in `just crosscheck` (2026-10-31)

**Kind:** Record
**Status:** Amended by F193
**Area:** crypto
**Held by:** crypto.crosscheck-sources

*Amended by F193 (2026-11-03): point 7: the vault is two published formats (F190), judged by outside readers of the primitives and, for the format only, by keepass-rs and rPGP; the clean-room reader is withdrawn.*

**Why.** A review of main on 2026-10-31 (`docs/ESTABLISHED.md` §9)
read each action's cross-check against the code it will have after
ESTABLISHED's switches. It found checks that compare a library with
itself or with its own lineage: Bitcoin Core signs, verifies and derives
with libsecp256k1, the app's curve library, in another version;
Faraday's QR encoder is a port of the encoder it is compared with; a
Base58Check test compares rust-bitcoin's encoder with itself; on a
builder with AES-NI both sides of aezeed run the processor's round, so
the Pi's software round is never compared. It found Faraday's second
version still written where vendored outside code (btclib) makes the
same refusals, actions with no area where a cheap outside judge exists,
and judges in tests that skip where a tool is missing. F79 named Python
references, F160 accepted libsecp256k1 as shared lineage and allowed Go
for LND's aezeed only.

**Decision** (owner, 2026-10-31; `docs/ESTABLISHED.md` §9). It amends
F79 and F160.

1. **Retiring Faraday's second version.** It is retired where others'
   code of another lineage covers the same inputs, and kept where none
   does, named in the action's `ours` (amends F160 point 8).
2. **Another version of the same library** is a collision for the
   curve maths, not for consensus and script logic. Where Bitcoin Core
   signs, verifies or derives a key, a pure-curve judge of another
   lineage sits beside it; Core still judges consensus, script and
   descriptor logic, PSBT handling and the encodings (amends F160
   point 7).
3. **A port is the same lineage** as its original; so is a library
   built on another.
4. **Required judges.** Every outside judge `just crosscheck` names is
   required there: a missing tool fails the run and names it, and its
   version is in the stamp. In `just`, tests that run an outside program
   and skip without it still skip; `just crosscheck` runs them with the
   skip turned into a failure. The tests that need GnuPG, paperkey,
   OpenSSL and sbverify stay required in `just`. Each tool is a
   `docs/DEVELOPING.md` prerequisite from the commit that first needs it
   (amends F79: the cross-check's references are Python's, Go's, Rust's
   and the distribution's programs, not only Python).
5. **Hex after base16ct** is checked against outside code: CPython's
   `bytes.fromhex`.
6. **Toolchains and sources.** Go reaches a released btcd, pinned by
   `go mod vendor`, for new uses; pull request 2521's copies stay for
   BIP-322. Rust programs outside the workspace, pinned by commit and
   SHA-256, never shipped and outside `cargo vet`, may be references.
   Node, a JVM, Swift and .NET are not taken now (amends F160 point 6).
   The bip39_slip39 wheel is vendored; embit in full only with
   Specter's importer, not now; btclib's change rule first, Bitcoin
   Core's watch-only wallet second; libsecp256k1's silent payments
   module is not a reference; aezeed is also run with the software AES
   round.
7. **The vault** waits for an outside reviewer (F160 point 3). A
   clean-room reader written by Faraday's authors or their agents from
   `docs/VAULT.md` alone is listed, not decided, and would stay
   Faraday's own.
8. ESTABLISHED §9.4 is each action's judges after the switches, and
   §9.7 the batches that build them, X1 to X30.

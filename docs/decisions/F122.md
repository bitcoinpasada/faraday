# F122 Make a new wallet: one press takes a stick, and Check opens the backup (2026-10-26)

**Kind:** Record
**Status:** Active
**Area:** backup

**Why.** On Bring in the sticks, Use Boot stick and then "This is the
stick for Vault 1" were two presses for one choice, and Create vault was
a third before the stick could be pulled. After Lock in, the Back up
card held one button and nothing else.

**Decision** (owner, 2026-10-25 and 2026-10-26; `docs/BACKUP-FLOW.md`
§4.2, §4.3, `docs/FLOWS.md`). In Make a new wallet a press on Use Boot
stick (or a stick's own name) takes that stick for the vault it is
asked for; a second confirmation is asked only where the stick reads as
one already bound to another place. No vault is unlocked until every
stick has been read. Then the Vaults step offers what fits: **Open
{vault}** for each vault found on the sticks, **Create {vault}** for
each new one, or both where both apply, in the order the person
chooses; nothing is unlocked by itself. Where only Create applies (no
vault found, none open in memory), Create a vault opens by itself; with
the boot stick in, the Pull sheet comes first ("Pull the stick to
create the vault, then your key") and the pull opens Create a vault. The
wallet's cards end at Check: its It matches
keeps Check open and becomes **Back up wallet**, which opens the backup
flow; there is no Back up card. Bring in the sticks has the flow's
Guided text, saying what is read from the sticks there and that nothing
is written to them yet.

This amends F53, whose Create's Back up step had one button, Back up
this wallet.

# F185 One build on every platform: the PC stick with `efi=disable_early_pci_dma`, the Pi with what Compatible carried (2026-10-31)

**Kind:** Record
**Status:** Active
**Area:** release
**Held by:** review

*Amends F145 (2026-10-31): one build per piece of hardware, not two. Amends F147 (2026-10-31): one image per piece of hardware, with no build to choose. Amends F150 (2026-10-31): the looser build is no longer named; it is the Pi's only build. Amends F153 (2026-10-31): KCMP is forbidden on the PC only, and the Pi's kernel is the one F153 describes.*

**Why.** The stick's second build existed because a test laptop did not
boot with `efi=disable_early_pci_dma`. That was another project's image:
a bootloader, an initramfs that finds the stick again over USB after the
hand-over, and the Intel graphics driver. Faraday's kernel is the EFI
program itself, with its root filesystem inside and the firmware's
framebuffer, so nothing it runs needs the devices the flag cuts off. The
stick built with the flag boots on that same laptop. Faraday has no PC
known to need the build without it. On the Pi, the stricter build kept
out the display, input and storage stacks that every screen but the
2.8-inch one needs, and the 2.8-inch screen's image boots on the panel
with them.

**Decision** (owner, 2026-10-31).

1. **The PC stick is one build.** Its built-in command line carries
   `efi=disable_early_pci_dma`, and the kernel check requires it. Its
   files are `faraday-x86_64-uefi[-dev].img`,
   `faraday-stick-VERSION-x86_64-uefi.img.xz` and
   `faraday-VERSION-BOOTX64.EFI`.
2. **The Pi is one build:** the kernel the Compatible build had, with
   vc4's display side through DRM, the sound core with no driver, USB
   HID and USB storage, under F153's rules for approving each device.
   The 2.8-inch screen's image is that kernel too. Its files are
   `faraday-pi3-waveshare-28dpi[-dev].img` and
   `faraday-pi3-hdmi[-dev].img`, released as
   `faraday-pi-VERSION-waveshare-28dpi.img.xz` and
   `faraday-pi-VERSION-hdmi.img.xz`.
3. **No `builds/` layer.** A board's lists and fragments are the board's
   own; `build=` is no argument of any recipe; a build tree has no build
   in its name. KCMP stays in the PC's forbidden list and is allowed on
   the Pi, where DRM selects it (F153).
4. **No compatibility** with the names of release 0.1.9's `-strict` and
   `-compatible` files: no fallback in any reader or writer.

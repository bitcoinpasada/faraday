# F328 The boot import's list stands on Files where On the stick stands; its passphrase step stays a sheet (2026-11-24)

**Kind:** Record
**Status:** Active
**Area:** stick
**Held by:** tests

*Amends F60 and F130 in the place only.*

**Why.** The list of the boot stick's files was a sheet over Home, though
Files is where a stick's files are listed and where they land. The owner
chose to draw the list in Files (question 46 A over 7 A).

**Decision** (owner, 2026-11-24).

1. **The list step is a card on Files** in the place of On the stick (a small
   panel: its tab, opened on). Files opens on it, not Home. In Faraday is
   headed "This session" while it is up.
2. **Nothing is read before Import**, as F130; only ticked files are read.
   The stick's own Import and Import and load are not drawn while the list
   is up, and refused if pressed. Pulling the stick leaves the person on
   Files, with "Put the stick back in to import".
   The one button reads "Import and load any keys" while a ticked file's
   name suggests it may hold a key (a text file, an image, a file of no known
   kind), else "Import"; the names decide, except that a vault under any
   name, told by the listing's twelve bytes (VAULT.md 1.1), reads "Import".
3. **Import works with the stick in** (46 A). While it is in, two lines say
   the stick is to be removed once the files are in and that a key from it
   loads as it is pulled, in the order of F60.
4. **Later** goes to Home with the import waiting; its row opens the list
   again. A different stick takes the list down, whichever page takes it (the
   backup flow too); Home's row compares the listing with the stick in, and
   a different one ends the import. That limit holds until Import is pressed,
   and Files then opens.
5. **The vault passphrase step stays the sheet over Home** (F60, F62): the
   passphrase field, its typing and keys exist only there. The list takes no
   key. The new-device sheet stands over Files first.
6. **A lock** wipes the list, what was read and what waits for the pull, as
   F60. The boot stick's settings are kept at a lock, so the first look is
   not repeated.
7. **The badge** on Files for a stick not yet visited stays after Later or
   Import with the stick left in, as it did when the list was a sheet; it
   goes when the stick is visited.
8. **Only a clean process shows the list**: with a secret held, the stick's
   return shows the Lock card and the list is taken down; Import asks
   nothing of the stick unless nothing has been held or typed, on Home's
   row too. With a secret held the list is down; Home's row raises it with
   Import off once one was held or typed. From the stick in another flow
   takes the list down as Later does.
9. **The stick's own actions stay**: Delete files, Write and the stick's
   menu are allowed while the list stands, with In Faraday's ticks; a
   name-taken answer and stopping a zeroing work as ever
   (owner, 2026-11-25: Delete, Write and the stick's menu allowed while the
   list stands). The list drops a file that is gone (deleted, or no longer
   on the stick at its size) and takes no new one; with none left the import
   ends. The import's own stick is not read to find a name Faraday holds
   while the list's step is set (up on Files, or left by the nav bar and not
   by Later, Import or From the stick). The listing, followed while the
   stick stays in, is compared with the one at the stick's return and at
   Home's row, until Import is pressed; a listing with the import's own id
   that it does not hold ends it at once. The list's card draws Delete
   files, Rename stick and each file's menu as the stick's own card does,
   while the import's stick is the one chosen and usable
   (owner, 2026-11-26). A file's Rename onto the name another file of the
   stick has, where the two are listed at one length and a vault can have
   it, is refused as Details is (the button off, with no line): the disk
   process would read and hash both files to word its answer. A rename to
   any other name goes as ever. A ⋮ whose place the listing has since
   given another file does nothing, and a Rename goes only to the stick it
   was opened on, while that stick lists the file. From Import until a
   file's read is answered it is not deleted or renamed, and until the
   last is, the whole stick is not zeroed: "Being imported".

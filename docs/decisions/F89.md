# F89 Silent payment signing counts a stated key only where the input's script commits to it (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** review

**Why.** BIP-375 signing is in core: `core/faraday-psbt/src/silent.rs`
checks a silent payment PSBT and adds this signer's shares, and
`core/faraday-bip/src/dleq.rs` makes and checks BIP-374 proofs. BIP-375's
reference validator takes the public key a PSBT states for an input
without tying it to that input's script. A coordinator could then state
any key, with a share and a proof that verify, and have outputs paid
that the recipient never finds. And BIP-375's text and its own vectors
disagree on the order of `k` among outputs that share a scan key.

**Decision** (owner, 2026-10-23).

- A key a PSBT states for an input counts only where the input's script
  commits to it. This is stricter than BIP-375's reference validator.
- Among outputs that share a scan key, Faraday accepts stated scripts in
  either order of `k` and writes them in output order, which reproduces
  every BIP-375 vector.

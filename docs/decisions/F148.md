# F148 One manifest for every cryptographic action, its Learn block generated from it, and `just lint` failing on a function it does not cover or whose code changed since review (2026-10-28)

**Kind:** Record
**Status:** Active
**Area:** security

**Why.** A person signing with Faraday cannot see from a screen which
standard it follows, which code computes it, what checks that code, or
where Faraday decided for itself. Those facts are written today in
several places by hand: `docs/STANDARDS.md`, `docs/AUDIT.md`,
`docs/KEYS.md`, `docs/COMPUTE.md`, the cross-check's areas, the Tools
tiles' tags and the Learn pages. Each drifts on its own (STANDARDS §8
lists five places where they already disagree with the code). Nothing
fails when a new cryptographic function lands with none of them, or when
one changes and its description does not.

**Decision** (owner, 2026-10-28; `docs/CRYPTO-LEARN.md`).

1. **A block per action.** Every Learn page that a screen with a
   cryptographic action opens carries a "How Faraday does it" block for
   that action. Its fields are fixed, in this order: Action, Standards,
   Implementation, Checked against, Cross-check (what the F79
   cross-check does for it: the second implementation, the vectors, the
   random cases, the known differences, the last passing run), Code,
   Secret handling, Limits, Faraday's own calls. Facts only. A missing
   check is written as missing, never left out.
2. **One manifest.** docs/crypto/actions.toml is the single source.
   The blocks, STANDARDS §1 to §7 and AUDIT §3 are generated from it.
   AUDIT §1 and §2, KEYS' reveals, COMPUTE's roots, the cross-check's
   areas, the vectors, the fuzz targets, the self-test's checks and the
   Tools tags are checked against it. The prose that depends on an action
   is named in its entry for review. The website renders from the pinned
   commit's manifest.
3. **Found from the code.** The lint finds the cryptographic functions
   by mechanical rules: the compute token in the crates that hold keys,
   a reveal, a primitive crate named, or a public function that reaches
   one. Each must be covered by an action, or be a not-cryptographic
   entry with its reason. That list's count only falls.
4. **Fingerprints.** Each action records a fingerprint of its code, its
   libraries' versions and its vectors. When one changes, `just lint`
   fails until the action is reviewed and re-stamped, and so does every
   action that uses it, each until its own review. The re-stamp
   recipe is the only writer: it lists every place the action touches,
   regenerates what is generated, and refuses while a named test, area
   or vector is missing, or while the cross-check stamp is stale.
5. **Reached from the screen.** A screen that offers an action carries
   **How Faraday does it** in its top app bar beside the ?. On the Pi
   it goes into the ⋮ first. It opens Learn on a How tab with the
   screen's blocks. The Starter does the same for writing and checking
   an image. A test over the screens holds it.
6. **No way past.** There is no silent exemption. A not-cryptographic
   function is an entry with its reason, counted. A hold on a check of
   this decision would need a decision naming its case (F136).

**Where:** `docs/CRYPTO-LEARN.md`; `tools/costs-lint` (the inventory
binary beside the costs lint); `tools/crosscheck/stamp.py` (its files
and vectors read from the manifest); `faraday/faraday-learn` (the
generated blocks); `faraday/faraday-core/src/learn.rs` (the How tab).

# F179 A Cryptography block's fields are Specification and Code; "implementation" names only a cross-check's second program (2026-10-30)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** crypto.independence-labelled, crypto.independence-said

**Why.** F177 used "outside implementation" for two things: in a
block's Implementation field, a library an action calls; in its
Cross-check, an independent program its results are compared with.
Readers took the first as "Faraday wrote its own implementation based
on that library". The Standards field lists BIPs, SLIPs, RFCs,
conventions and Faraday's own specifications: those are specifications.

**Decision** (owner, 2026-10-30). It amends F177 point 1, its words
only; F177's points 2 to 5 stand.

1. **Specification.** The block's field, and the website's column,
   "Standards" is "Specification".
2. **Code.** The field "Implementation" is "Code". Its lines are
   "Library: <crate> <version>, by <author>.", one per library, then
   "Faraday's code: <crate path>: <what it adds>.". "Outside
   implementation" and "Own implementation" are not used there.
   "Implementation" names only a cross-check's second program. The
   field that links the release, file and function of each entry, which
   was "Code", is "Source".
3. **Libraries reached through another crate** (owner, 2026-10-30).
   A library the action's code reaches through another Faraday crate is
   listed on the action too, after its own crate's: "Library: pbkdf2
   0.13.0, by the RustCrypto developers, through core/faraday-crypto.".
   The manifest names each in `[action.implementation]`'s `through`, a
   list of `{ library, crate }`. `docs/crypto/check.py` fails an entry
   whose crate does not depend on the library, whose library has no
   `[library.*]` table or is not in Cargo.lock, whose crate is the
   action's own or whose library is in `libraries` already, and one whose
   crate the action's functions do not reach in the inventory's call
   graph. That every library reached is listed is not checked. The
   website's Code cell writes it "Library: <crate> <version> (through
   <crate>)", and its Libraries list counts the action under it. The
   schema stays 4: `through` may be absent.
4. **The cross-check's words.** An action's cross-check compares
   Faraday with **others' code** (class `outside`), with **Faraday's
   second version** (class `own`, a second implementation Faraday's
   authors wrote, not checked against an outside source), or both
   (`outside-and-own`); an action with none is **not cross-checked**.
   A block's line reads "Compared with others' code: <author>.". The
   cross-check README's table heads its columns "Others' code" and
   "Faraday's second version". On the website the pills are "Others'
   code", "Faraday's second version" and "Not cross-checked" for the
   cross-check, and "Published" and "Own specification" for the
   specification.
5. **The website's /cryptography.** Its title is "Cryptography in
   Faraday: specifications, code and checks"; its columns Action,
   Specification, Code and Cross-checked with; the Code cell two
   labelled lines, Library and Faraday's code, with no pill; the key
   explains Specification and Cross-checked with only; the closing list
   is "Libraries". Under the title come the enforcement lines, then
   "Faraday's approach" (`docs/CRYPTO-LEARN.md` §11.1), which opens with
   STANDARDS §0's summary.

and `block.rs`; `tools/crosscheck/README.md`.

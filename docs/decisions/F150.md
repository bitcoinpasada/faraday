# F150 The looser build is named Compatible, every HDMI screen shares one image, and the Pi 4 is built on the terms its reach asks (2026-10-28)

**Kind:** Record
**Status:** Amended by F153
**Area:** release
**Held by:** review

*Amended by F153 (2026-10-28): the HDMI screen's USB touch is let in by tapping a target, not trusted for its name, and the Compatible kernel is the board's source with no patch of Faraday's own.*

**Why.** "Open" read as open to attack, for a build Faraday calls safe in
practice; what sets it apart is that it works with more hardware. An HDMI
screen tells the Pi its size and modes (its EDID), so the Pi needs no
screen-specific lines for it, unlike a DPI or DSI panel, which must be
named on the card before the Pi starts. The Pi 4 starts from a boot
loader kept in an EEPROM on the board, which a card carrying
`recovery.bin` can rewrite: a fresh card is then no longer a clean start,
as it is on a Pi 3 (`docs/IMAGES.md` §9).

**Decision** (owner, 2026-10-28; `docs/IMAGES.md` §1 to §3, §9).

- **Strict and Compatible.** The build that works with more hardware is
  Compatible, in the documents, the release's file names, the recipes
  (`build=compatible`) and the website. Strict keeps its name.
- **One image for every HDMI screen.** A monitor with a USB keyboard and
  mouse and Waveshare's 10.1-inch HDMI panel with its USB touch take one
  Compatible image; the 2.8-inch and each DSI panel keep their own.
- **The Pi 4 is built**, on the same images as the Pi 3, on these terms:
  no boot loader update is ever on a Faraday card; `SPI_SPIDEV` and
  `SPI_BCM2835` are forbidden in its kernel; the hardware page says its
  security is close to a PC's, its boot code on the board; and its owner
  is told to restore Raspberry Pi's boot loader with Raspberry Pi Imager
  before first use, a wire to test point TP5 locking it in hardware.

**Amends** F145 (the name Open; the 10-inch HDMI panel's own image) and
F147 (the Pi 4 planned, now approved on the terms above).

# F196 A Rust file may grow to 5,000 lines, and the function counts are no longer ratchets (2026-11-03)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** structure.size, structure.ratchet-raised

*Amends F74: its size rule (no file over 2,500 lines except those counted, a ratchet on functions over 100 lines and on `too_many_arguments` allowances) is replaced by this decision. F74's structural rules stand.*

**Why.** The per-file count split code by line count, not by where it
belongs, and put unrelated moves into feature commits. It did not touch
the real concentration, which is the size of `faraday-core` as a whole.
The counts of long functions and of functions with many arguments only
pushed a marker's number around.

**Decision** (owner, 2026-11-02; `docs/STRUCTURE-PASS.md` §7.2).

1. **A `.rs` file may grow to 5,000 lines.** Over that, `lint-layout`
   fails. No review is required between 2,500 and 5,000 lines.
2. **The frozen per-file counts go.** The files already over 5,000 lines
   stay listed in `tools/lint-layout.counts` at their size, and their
   count only falls, until each is split under the ceiling.
3. **The counts of `expect(clippy::too_many_lines)` and of
   `allow(clippy::too_many_arguments)` are no longer ratchets.** Each
   marker carries `reason = "..."`.
4. **F74's structural rules stay:** the code map, the shrinking list of
   files allowed an `impl Faraday`, `Faraday`'s field count,
   `lint-secrets`, `cargo vet`. `lint-tokens` and `touch-targets` are
   unchanged.

**Open:** `lint-layout` does not yet check that each marker carries a
`reason`; a later change adds the check.

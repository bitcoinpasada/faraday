# F156 Schnorr signatures are made with zero aux_rand (2026-10-28)

**Kind:** Record
**Status:** Active
**Area:** security
**Held by:** review

**Why.** BIP 340 lets a signer pass any 32 bytes as aux_rand, zero
among them, and recommends fresh randomness as a defence against fault
and side-channel attacks on the signing device. The nonce is derived
from the private key, the message and aux_rand, so zero repeats no
nonce across messages. Faraday signed with zero and no decision said
so.

**Decision** (owner, 2026-10-28).

1. **Zero.** Every Schnorr signature the app makes, a taproot input or a
   message, passes zero aux_rand: it is deterministic.
2. **Why zero.** A deterministic signature can be made twice and
   compared byte for byte, which is Faraday's own check against a
   faulted signing (each signature is made twice and verified before it
   is written); it can be recomputed by anyone holding the key, so the
   device cannot choose a nonce that carries the key out
   (`docs/ANTI-EXFIL.md`); and it is checked byte for byte against
   BIP 340's vectors and the cross-check. ECDSA is deterministic the
   same way, by RFC 6979.
3. **What it gives up.** The hardening fresh aux_rand adds against an
   attacker who measures or glitches the machine while it signs. Faraday
   runs on general-purpose computers, where that attack is outside what
   fresh aux_rand could stop.

**Where:** `faraday/faraday-keys/src/psbt.rs`, `faraday/faraday-keys/src/message.rs`
(`Aux::default()`), `core/faraday-psbt/src/sign.rs`.

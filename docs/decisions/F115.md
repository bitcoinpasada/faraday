# F115 A key flow opened from Make a new wallet has Cancel, back to it (2026-10-24)

**Kind:** Record
**Status:** Active
**Area:** design
**Held by:** review

**Why.** F51 gives Cancel to every flow with a sidebar row. New key and
Make codex32 shares opened for a slot of Make a new wallet have no row
of their own, so they had no Cancel, only a back link that drops what
was entered without asking. And a Keys card whose one choice is its key
flow is a step that asks nothing.

**Decision** (owner, 2026-10-24; `docs/FLOWS.md`, Cancel item 6 and
the Keys card; `docs/WALLETS.md` §5). It extends F51:

1. A key flow opened from Make a new wallet for a slot shows **Cancel**
   until its key is locked in. It ends no flow: it returns to Make a
   new wallet on its Keys card, the slot as it was, and asks first,
   with Material's dialog, only when rolls, characters, words or a
   passphrase would be discarded. New key opened on its own keeps no
   Cancel.
2. Make a new wallet passes over its Keys card when the card would
   offer one way on only (a single key with no key in the session, no
   key file in the Inbox and no vault's key; or a backup in shares):
   the Continue before it opens that key flow for slot 1. Keys stays in
   the steps, done once the key is locked in, and the key flow's Cancel
   returns to the card before Keys. A multisig, and a slot with more
   than one choice, keep the card.

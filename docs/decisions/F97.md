# F97 .oskb files are no longer read; the vault's record layouts are its own (2026-10-23)

**Kind:** Record
**Status:** Active
**Area:** backup

**Why.** Faraday never wrote an `.oskb` file. The only such files came
from the project it was forked from, and nothing Faraday itself makes
needs reading one back. Keeping a reader meant keeping a second encrypted
format, its Argon2id run on opening one, its reference decryptor and its
vectors, for files nobody here has.

**Decision** (owner, 2026-10-23).

- Faraday does not read `.oskb` files. The reader and its sealing
  functions, the "Read an encrypted backup" source, the Inbox's
  recognition of the file, the reference decryptor, the vectors, the
  sample and the Learn page are gone. The Inbox shows such a file as any
  other file it does not read.
- The vault is unchanged on disk. Its key, note and recovery sheet
  records had borrowed four payload layouts from `.oskb`; they are now
  the vault's own, written in `docs/VAULT.md` §7 byte for byte as they
  were and read and written by `faraday/faraday-vault/src/layouts.rs`.
  No cryptography changed, and existing vaults and `tools/vectors/vault/`
  open unchanged.
- KDBX 4, the one encrypted file Faraday writes for others, stays in
  `faraday-backup` (`docs/KDBX.md`).
- The format's description is kept as written in
  `docs/history/BACKUP-FORMAT.md`.
- No migration is needed: nothing Faraday wrote is affected.

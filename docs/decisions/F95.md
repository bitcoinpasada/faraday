# F95 Codex32QR/v1-48: read, shown, tested (2026-10-22)

**Kind:** Record
**Status:** Active
**Area:** keys

**Why.** The Codex32QR profile (its author's SeedSigner fork, MIT) puts
one 48-character codex32 string in a QR code, as SeedQR does for words.
Faraday already reads the text of such a code as any codex32 string; it
did not take one in Scan a SeedQR, drew none, and no test scanned one.
The plan is `docs/CODEX32.md` §10.

**Decision** (owner, 2026-10-22).

- **Read**: every scanner that takes a codex32 string takes a Codex32QR
  code, and Add a key's Scan a SeedQR takes one too, opening the codex32
  form with the string in. A share scanned alone waits for the rest of
  its set; nothing is loaded until enough strings are in.
- **Shown**: wherever Faraday shows one 48-character string, a toggle
  draws it as a Codex32QR code (upper case, byte mode, version 3, error
  correction L, the standard quiet zone), a secret masked as a SeedQR
  is.
- **Tested**: against the profile's published vectors and pictures,
  kept with their source, commit and SHA-256 under
  `tools/vectors/codex32qr/`.
- **Nothing longer**: no QR is drawn for a 74- or 127-character string,
  and none is read but as plain text, until the profile's author
  publishes a profile for them. No profile is made up here.
- **A share index already in** (the profile's rule): the same string
  again is ignored; a different string at the same index asks before
  replacing the one held, showing both with their differing boxes.

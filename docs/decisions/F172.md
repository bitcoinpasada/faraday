# F172 A BIP-85 password out of Faraday names neither its parent nor its index; in a vault its entry keeps both (2026-10-29)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** keys.child-vault-only

**Why.** F166 left a password out of BIP-85 as it was: its vault entry
titled "BIP-85 Password (base64) · 3dca6805 · index 0" with the path in
its notes, and its file out unprotected named
`bip85-3dca6805-passwordbase64-0.txt` with the path inside. An entry goes
out of Faraday as a KeePass file, named after its title and carrying its
title and notes, so whoever holds that file learns the key the password
came from and where. A password is the person's to deny as a child seed
is: what is written for others carries no more than the password.

**Decision** (owner, 2026-10-29: treat BIP-85 passwords as child seeds;
exports leave out the parent and the index). This extends F166 item 2 to
a Base64 or Base85 password, and replaces, for those two, the last
paragraph of F166, which keeps applying to a WIF, an extended private key
and hex.

1. **In the vault, as before.** A password saved into a vault is an entry
   with the title BIP-85 gives it, naming the parent's fingerprint and
   the index, and the path in its notes: the vault is where the person
   keeps what makes it again. The entry's format is unchanged.
2. **A KeePass export carries the password alone.** An entry whose title
   is the one BIP-85 wrote goes out titled "Password", in a file named
   `password.kdbx` (`password-2.kdbx` and on, beside any other waiting in
   the Outbox). Any line of an entry's notes that is a BIP-85 path
   (beginning `m/83696968'`) is left out of every KeePass export, whatever
   the entry's title; the username and URL go as they do for any entry.
   An entry the person has retitled goes under the title they gave it.
3. **A password out unprotected is a file of its own.** **Out
   unprotected…** writes `password.txt` (`password-2.txt` and on, beside
   another waiting), holding the password and nothing else.

Not taken: dropping the parent and the index from the vault entry, which
would leave the person nothing to make the password again with; a new
field marking an entry as BIP-85's, which would change the record format
and miss entries already written.

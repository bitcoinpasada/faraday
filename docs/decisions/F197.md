# F197 The full cross-check runs before a release, and the tip between releases is not kept cross-checked (2026-11-03)

**Kind:** Record
**Status:** Amended by F239, F247, F259
**Area:** repository
**Held by:** crypto.crosscheck-stamp

*Amends F79 and F148 (point 4): `just lint` no longer checks the stamp or the fingerprints.*

*Amended by F239 (2026-11-10): point 2's fresh run may be a combination of runs at one fresh seed and scale. Amended by F247 (2026-11-11): point 4: the guide's Cryptography tab shows the counts, not the Learn pages.*

*Amended by F259 (2026-11-14): point 2: the actions carry no fingerprints, so no action is reviewed and re-stamped before a release, and `just lint-release` is the cross-check's stamp alone.*

**Why.** Each change to a crypto crate made the stamp and the actions'
fingerprints stale for every other change in progress, so they were made
again at every push, for a record that is not a security control
(`docs/CROSSCHECK.md` §10.2). What a person runs is a release, and a
release already runs the cross-check with a new seed.

**Decision** (owner, 2026-11-03).

1. **The full cross-check runs before a release,** never on a schedule.
   The tip between releases is not kept cross-checked, and the documents
   say so where people read about the cross-check.
2. **A release is held.** After `just crosscheck --fresh` and a
   review of each action whose code changed (withdrawn by F259), `just
   lint-release` (the stamp and `docs/crypto/check.py check --release`;
   the stamp alone since F259) must pass.
3. **Every other check stands.** A change to an area's code runs that
   area, and the tests, the reviewers and the rest of `check.py check`
   and `gen.py check` are unchanged. A change commits no stamp and no
   fingerprint.
4. **Until the next release,** the Learn pages of a test build show the
   last release's seed and case counts, and an area added since shows 0
   cases.

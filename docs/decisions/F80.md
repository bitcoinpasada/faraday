# F80 A stick or Pi card has a 64 MiB boot and a 128 MiB FAT32 data partition (2026-10-22)

**Kind:** Record
**Status:** Active
**Area:** stick

**Why.** The stick had a 48 MB FAT32 EFI system partition, sized by
FAT32's 65,525-cluster minimum and holding a boot file of about 13 MB,
and a 32 MB FAT16 data partition. The Pi card had a 32 MB boot
partition holding about 16 MB, and the same data partition. Neither
left room for a much larger boot file, a 32 MB data partition holds
about two vaults at their largest (16 MiB each), and FAT16's top folder
has a fixed number of entries (`docs/LARGE-FILES.md`).

**Decision** (owner, 2026-10-22).

- The boot partition is 64 MiB on the stick (FAT32, `FARADAYBOOT`) and
  on the Pi card (FAT16, as `mkfs.fat` makes it at that size; the Pi
  firmware reads either). That holds a boot file of 30 MB twice over.
- The data partition (`FARADAYDATA`) is 128 MiB FAT32 on both
  (`mkfs.fat -F 32 -s 2`: clusters of 1 KiB, half the FAT lookups of
  the 512 bytes it would choose, and over FAT32's 65,525-cluster
  minimum, which 2 KiB would not be).
- The stick's image is 193 MiB and 20 KiB (1 MiB before the first
  partition, the backup GPT after the last); the Pi card's is 196 MiB
  (4 MiB before the first partition). Either fits any medium sold as
  256 MB, which is the minimum stated. The layout is fixed and
  reproducible; nothing fills the rest of the medium.
- A stick made before, with a 48 MB boot partition, is refused by
  Upgrade a Faraday stick and by the Starter's keep data, which write a
  64 MiB boot partition. Its files are moved to a new stick by hand, as
  with F67. Its 32 MB FAT16 data partition is still read and written as
  any stick's.
- Writing a stick or card and reading it back takes about twice as long
  as before; the compressed download barely changes.

# F282 A wallet's key is made on Make a new wallet's Keys card, from dice by default (2026-11-17)

**Kind:** Record
**Status:** Active
**Area:** wallets
**Held by:** review

*Amends F115 (2026-10-24): its point 2 no longer holds, since the Keys card always shows; point 1, Cancel in a key flow opened for a slot, holds for New key opened from Other ways. Amends F240 (2026-11-10): a slot whose key is BIP-39 words makes it on the Keys card, and New key is one press away from there; the rest of F240 holds.*

**Why.** Making the key for a new wallet took a second flow: New key
opened over Make a new wallet, its own cards for Start, Length,
Randomness, the entry and Key, then back. Its Start asked again what the
Backup card had answered, Length had no count chosen and Randomness no
source, so the common case, a wallet's first key made from new words,
took six presses before a single roll. The Keys card always shows now
(F115's pass-over went with the vault counters), so it can hold the
making itself.

**Decision** (owner, 2026-11-16; `docs/FLOWS.md`, New key and Add a key;
`docs/WALLETS.md` §5).

- **Where.** On a single key with Backup set to Words, and on Key 1 of a
  multisig while no slot holds a key made here, the empty slot holds the
  making in place: Length, the dice entry, the words, then the slot's
  button. With Single key ticked and Words answered when Make a new
  wallet opens, the presses on Kind and Backup lead straight to it.
- **Length.** 12 words · 24 words, 12 chosen when the slot opens.
- **Randomness.** Dice, already chosen, by the procedure the Randomness
  card recommends (rolls that name the words): the dice entry under
  Length with the count still needed (59 at 12 words, 117 at 24).
  Changing Length after rolls are in drops them, as on Length now.
  Nothing is collected until the person rolls, so the standing rule that
  randomness is never collected passively holds. A key from dice alone
  takes nothing from the system and can be worked out again elsewhere
  (`docs/OWN-RANDOMNESS.md` §1). The device's own randomness is one press
  away and unchanged: This device (mixing in what the person added on
  Add randomness, §2.3) and a mix of dice or this device with other
  sources, both under **Other ways**.
- **Make the words** once the last roll is in: the slot shows the words
  masked, **Show words**, and **Add a passphrase** (Passphrase,
  Passphrase again; unequal fields hold the button).
- **The button.** A single key: **Make the wallet**, which does what New
  key's Lock in does there now (the key loaded under the self-test gate,
  marked made here, the wallet made, Check opened). A multisig: **Lock
  in**, which fills the slot.
- **Other ways**, one press away under the slot: New key as F240 has it
  for the slot, for This device alone, typed words, a SeedQR, codex32 and
  SLIP-39 shares, and the other dice procedures, coins and cards. A
  single key with Backup set to Shares keeps New key opening on codex32's
  cards; a key from a vault, a key file or a key already loaded fills a
  slot as now.
- **Later multisig slots** keep **Scan its xpub** first, with **New
  words** beside it, which opens the same making in that slot.
- **Leaving.** Rolls and words not locked in are dropped when the person
  leaves Make a new wallet (another screen, Lock, Start over, Cancel) or
  changes Kind or Backup; nothing made on the card is kept. Cancel asks
  first while rolls or words are on the card, as F115 point 1's question.
- The words are still checked in Back up, after the wallet is made; the
  self-test gate and the demo's refusal stay where Lock in has them.

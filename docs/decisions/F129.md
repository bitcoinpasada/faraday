# F129 A secret saved as a plain file asks for a hold (2026-10-26)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** tests

**Why.** A secret saved outside any vault, as a plain file on a stick
or in a computer's folder, can be read by anyone who has the stick. The
secret sheet asked the person to tick a line before **Unprotected**
let it out, Back up asked at **Lock and write** for a seed's file at a
place, and Transfer's Receive saved a secret as asked with no question
at all.

**Decision** (owner, 2026-10-26).

- Saving a secret (seed words, a SeedQR, a codex32 string, a private
  key, a passphrase, a secret note) as a plain file, outside a vault,
  asks for a hold on one sheet, **Save without encryption?**: a Material
  3 dialog with DESIGN §4.13's hold, as wiping a stick and deleting from
  a vault take. Faraday allows it because a plain secret on a stick is
  the same as the secret on paper: as safe as where it is kept.
- The sheet's two lines: "{name} goes on the {stick} as a plain file,
  outside any vault. Anyone who has the {stick} can read it." and "That
  is as safe as writing it on paper: it is as safe as the place you keep
  the {stick}." Its hold, **Hold to save without encryption**; beside
  it **Put it in a vault**, which does what the secret sheet's **Save
  into {vault}** does, where a vault is open and the secret can go into
  it, else **Cancel**. Let go before the end, nothing is saved.
- Where it is asked:
  1. the secret sheet's **Unprotected** (every secret that leaves the
     session as a file, an Inbox file a stick visit would copy to
     another stick among them): the tick is gone, the hold confirms;
  2. Back up's plan, when a drop or a form puts a seed's words, SeedQR
     or passphrase file, or a codex32 string's file, on a stick at a
     place: once for that file, at the drop, before the lock; **Cancel**
     leaves the plan as it was. A file held for asks nothing at **Lock
     and write**, and the write asks nothing more than the stick's own
     hold. Such a file the plan came with, from a preset or a plan saved
     before, is asked at **Lock and write**, once per file, before
     anything is made; **Cancel** there stops the lock and leaves the
     plan as it is (it undoes what asked, as the drop's Cancel does);
  3. Transfer's Receive, before it saves a file that holds a secret
     into the folder ("{name} goes into {folder} …", kept on "the
     computer"); **Cancel** saves nothing.
- A secret saved into a vault asks for no hold.
- This sheet carries one line of explanation, the second, on a working
  sheet: an exception the owner chose to the rule that a working screen
  carries labels, values and actions, never an explanation
  (`CLAUDE.md`).

# F212 GitHub's cache may hold compiled dependencies, never Faraday's own crates (2026-11-04)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** repo.ci-check

*Amends F183 (2026-11-04): its third point barred all build output from the cache; everything else it says holds.*

**Why.** Every job of the check that compiles starts from nothing, and most
of what it compiles is dependencies that change only when `Cargo.lock` or a
manifest does. A check waits for that on every push and pull request.

**Decision** (owner, 2026-11-04).

1. **Compiled dependencies only.** Before a job's cache is saved,
   `.github/actions/save-deps/keep_dependencies.py` removes everything but
   what cargo built for packages with a registry or git source, as `cargo
   metadata` names them. Faraday's own crates, test binaries and final
   binaries never go in, so the code a check is judging is always compiled
   in that check.
2. **Written only by a push to main,** after that job's work has passed. A
   pull request and a run started by hand only read it, so nothing outside
   main can put anything in front of a later check.
3. **A release commit's check is uncached.** It compiles everything, as a
   clone without GitHub would: the check started by hand with `uncached`.
4. **The key names what was compiled:** the job, the toolchain file, every
   manifest and lock file. Any change to them starts that job's dependencies
   again from nothing, with no partial match to an older cache.

The check is still `just`, and passes or fails the same without the cache.

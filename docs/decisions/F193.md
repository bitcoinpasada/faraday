# F193 The vault's judges: libraries over the app's primitives judge the file format only, no Node yet, and CPython's tomllib reads the vault's contents (2026-11-03)

**Kind:** Record
**Status:** Active
**Area:** crypto
**Held by:** crypto.crosscheck-sources

**Why.** F190 point 11 names keepass-rs, rPGP, pysequoia and OpenPGP.js
among the judges of the KDBX and QR vaults. F192 does not count a judge
whose primitives are the app's own for the cryptography (keepass-rs and
rPGP run RustCrypto, as the app does; `docs/ESTABLISHED.md` §9.5), and
takes no Node now (F192 point 6), which OpenPGP.js needs. F192 point 7
still describes Faraday's own vault container, which F190 replaces. The
TOML tree inside a vault (`vault-contents`) had no judge.

**Decision** (owner, 2026-11-03; `docs/ESTABLISHED.md` §9.4, §9.5). It
amends F190 point 11 and F192 point 7.

1. keepass-rs and rPGP judge the vault's file format only: both ways,
   each opens the files the other made, but neither counts as an
   outside check of the primitives. The primitives are judged by
   pykeepass and `keepassxc-cli` for KDBX, and by Debian's `sq`, over
   Nettle, for OpenPGP.
2. OpenPGP.js is not taken until Node is (F192 point 6). pysequoia
   counts for the primitives only once its backend is checked.
3. CPython's `tomllib` reads the TOML tree of every vault the area
   writes, beside Faraday's reader, in the F79 area `vault`.
4. F192 point 7 reads: the vault is two published formats (F190),
   judged as points 1 to 3 say; the clean-room reader of Faraday's own
   container is withdrawn with the container.

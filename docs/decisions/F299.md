# F299 One registry of the forms a key comes in: every list of forms reads it (2026-11-20)

**Kind:** Record
**Status:** Active
**Area:** keys
**Held by:** tests

**Why.** The owner (2026-11-20): Add a key's `forms::Form` is the only
place that names the forms a key comes in, yet nine other lists say the
same things again by hand: New key's Start, Check's backup menu, the kinds
a seed scanner loads, the Inbox's seeds, the samples, Create's Backup
card, the backup plan's copies, Convert's targets and what makes a master
key. Each new form was added to each list by hand and some were missed: a
Krux code is sent to the words on New key's Start, and the seed scanners'
kinds leave out the Krux code and the SLIP-39 and codex32 shares. Two
more forms are coming (F300), and the screens that take a key are to share
one set of ways in.

**Decision** (owner, 2026-11-20; `docs/KEY-FORMS.md`).

1. **One description.** A form's name, how it is typed and scanned,
   whether a passphrase goes with it, what it makes, what it is written as
   on paper and in files and how a copy is checked are stated once, in
   the registry, and read from there by every screen, flow and plan that
   lists forms.
2. **Exhaustive.** Every map from a form, or to one, names every form,
   with no catch-all arm, so a new form fails to compile wherever it is
   not handled.
3. **Append only.** A form's place in the registry is its code: forms are
   added at the end and never moved or removed. What a screen shows first
   is that screen's own list.
4. **Its own crate.** The registry is a small crate below `faraday-plan`
   and `faraday-keys`, holding plain facts only: no secret, no parser and
   no type of `faraday-core`. The scan kinds, the camera's purposes, the
   actions and each screen's list stay in `faraday-core`, each mapped
   from the registry.
5. **What stays its own type.** `faraday_keys::Material`, which holds the
   secret, has one variant for each thing a form makes. Convert's
   `Target` keeps every writing Convert offers, most of which are no form;
   which targets a key offers follows from its form. The Inbox's seeds keep
   their Inbox places. Each maps from the registry exhaustively.
6. **One component for the ways in.** Every screen that takes a key draws
   the same component: its forms from the registry, which ways show first
   from the screen, and the rest under **Other forms**. A test for each
   screen checks that it offers every form it takes.
7. **The plan's spellings stay.** A copy is kept as a form's output on a
   medium; every spelling already written into a vault's notes reads back
   as the same copy.

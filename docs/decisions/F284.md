# F284 A hand-started run's tests may be split over several runners (2026-11-17)

**Kind:** Record
**Status:** Active
**Area:** repository
**Held by:** repo.ci-check

*Amends F243 (2026-11-17): the crate tests of a hand-started run may run on several runners, no longer on one; the rest of F243 holds.*

**Why.** A whole crate's tests, or several crates', took 13 to 28 minutes
on one runner, where the same tests split over 14 runners take under 3
minutes after the build. The check already splits its tests this way (F183).

**Decision** (owner, 2026-11-17).

1. **`targeted.yml` takes `partitions`**, a number from 1 to 14, 1 by
   default. For a run of crate tests it starts that many runners as a job
   matrix; runner *i* runs `cargo nextest run --partition hash:i/n`, so
   the runners together run each test once, and a runner whose share
   holds no test passes (`--no-tests=pass`). A lint recipe or a tool
   (`fmt`, `clippy`, `check`) runs on one runner, and the inputs check
   refuses `partitions` above 1 for them or without a crate. A runner past
   `partitions` is skipped.
2. **Each runner builds what it runs**, from the check's cache, which it
   reads and does not save (F212); no artifact passes between runners.
3. **F243's other terms and F183's limits hold**: started by hand, one run
   a branch, inputs checked and passed through `env:`, read-only, no
   secrets, actions pinned by commit.
